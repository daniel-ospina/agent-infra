Closes #2843

## What this changes

The issue's own comment thread says PR #3231 (merged `8d9a936b8`) closed the **resolver** half and
left the **install** half untouched. Re-measured on `origin/main` @ `e3c5fb8f0`:

| the issue's proposed fix | state on `main` before this PR |
|---|---|
| 1. ship the instrument with the gate | ❌ `install_spawn_gate()` installed `$DEST/bin/pi` only — `ls ~/.pi/agent/bin/` → `pi`, `pi.bak-bootstrap` |
| 2. self-test at install time | ❌ neither installer ran the installed gate |
| 3. say which candidates it tried | ✅ done by #3231 |
| bound: "an abstention is not recorded durably the way a refusal is" | ❌ no fork column: `allowed`-with-the-floor-OFF and `allowed`-with-the-floor-ENFORCED wrote identical rows |

This PR delivers 1, 2 and the bound. Item 3 is not re-opened.

1. **`pi-bootstrap/cell-install.sh`** — `install_spawn_gate()` installs
   `scripts/orchestrator-harness/capacity.sh` → `$DEST/bin/capacity.sh` (the resolver's `$_sgc_here`
   candidate), and `die`s if the checkout has no module to ship rather than installing half a pair.
   `guard_spawn_gate()` byte-compares it **and drives it**: `spawn_fork_state` is run with `O`,
   `O_WORK`, `AGENT_INFRA_PATH` and `HOME` scrubbed, so the only candidate left is the placement under
   test. `ok` and `refused` both pass (a starved box must not fail its own install); the failure is
   obtaining **no reading** — `unknown`/`nodeploy`.

2. **`pi-bootstrap/setup.sh`** — the same pair plus the same install-time self-test, for the Mac.

3. **`scripts/orchestrator-harness/spawn-gate.sh`** — `pi_gate_ledger` appends a 13th field,
   `fork=<ok|refused|nodeploy|unknown>`, at all five call sites, defaulting to `fork=unknown` when a
   writer omits it. Append-only: fields 1–12 keep their positions, so `cut -f1-10` readers and
   `stall-fix.sh` are unaffected. "Did the process-headroom floor run" is now
   `awk -F'\t' '$13 != "fork=ok"'` instead of a grep through per-lane logs that rotate.

**Why not the env-var alternative the issue offers** (`export O` / `SPAWN_GATE_HARNESS_DIR` from the
shim): an environment variable is absent in exactly the contexts this defect lives in — launchd, a
`tmux new-session` one-liner, cron, an interactive shell — while directory adjacency cannot be absent.
`O` also changed meaning (#2095: it is the *state* dir now, and a shim inheriting it would resolve
`capacity.sh` from a directory holding only `logs/` and `state/`).

  instrument in place.
