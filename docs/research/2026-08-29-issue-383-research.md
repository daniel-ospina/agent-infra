#### Axis: Org-Infra/Architecture (medium+ — enforcement gate semantics)
- **[pitfalls]** Silent-skip-on-missing-config is a recognized anti-pattern (env checks that skip code paths without logging; fixes: warn before early return, distinguish "found nothing" vs "couldn't check", surface skip reasons) — skillsauth.com *code-silent-degradation*. → The no-board skip must carry an explicit advisory, never a silent pass.
- **[pitfalls]** "Skip only when the skipped input cannot possibly carry the signal you're gating on; otherwise the gate must fail-closed with a clear reason" — dev.to *every-safety-gate-has-a-failure-direction* (J. Longshore). → Validates the narrow-predicate design: git-local checks (C4 behind-origin, C1 guard/dup) retain signal → still run in no-board mode; pure-board checks skip LOUDLY.
- **[pitfalls]** "A passing check and a working check are not the same thing" — a gate that structurally can never fail is decoration; clean-scan and didn't-run look identical on a dashboard; gates should fail loud when they could not do their job — blog.elvatis.com *when-a-security-check-can-never-turn-red*. → The skip must be audit-distinguishable (token mode field + audit event + advisory).
- **[pitfalls]** Empty-gate-defaults-to-success is a structural flaw — "make empty gates loud: exit non-zero or return an explicit UNGATED status" — dev.to *can-your-verify-gate-actually-fail*. → Reinforces: no-board CLEAR is an explicit distinguishable verdict, not an empty pass.
- **[canonical]** GitHub Actions: a skipped job does NOT satisfy a required check (skipped ≠ success); canonical shape = an always() gate job translating skipped→success, or moving the conditional inside the job so it always runs and exits 0 with a distinguishable reason — latchkey.dev (branch-protection skipped-job). → Maps to: checker always runs, emits explicit no-board-skip CLEAR; the gate passes it with an audit marker.
- **[canonical]** SonarQube quality-gate model: explicit statuses PASSED/WARN/FAILED — "skipped" must be represented separately to be machine-auditable; pattern = skip enforcement of a condition while still computing the reviewable data — docs.sonarsource.com. → Token payload must gain a mode/note field (extend `_apply_token`); the enforcer gate treats CLEAR-with-mode as pass but the audit event carries the mode (never byte-identical to a board CLEAR).

#### Axis: Config (medium+ — vendoring/sync + CI wiring)
- **[precedent]** VendKit: checksum manifest + sync lane (each upstream upgrade = one reviewed PR, never silent) + gate lane (hand-edit/delete of a vendored file cannot merge) + composition invariant — closest external analog to the repo's templates/+sync-ci-workflows.sh pattern (#303/#555); the #383 swarm→agent-infra direction needs a documented sync/drift mechanism — github.com/jameswbaxter/vendkit.
- **[precedent]** Semantic vendoring: must record the exact upstream commit (merge base) durably, else local-vs-upstream edits become inseparable — solmaz.io. → Record swarm base rev 29dd67e8 + the 10-line `_REPO_ROOT` patch as the first local edit (VENDOR.md / manifest next to the vendored files).
- **[precedent]** inrepo (`verify` in CI catches drift, pinned commits, reviewable patches) + sync-vendored.yml (CI compares sorted {name,rev} manifest sets; auto-PR with compare URLs) — drift-gate patterns if a CI drift check is added — github.com/inthhq/inrepo, github.com/hanamizuki/solopreneur.
- **[canonical]** Reusable workflows: `workflow_call` + `inputs` + `uses: org/repo/.github/workflows/f.yml@main` + `with:` (same-repo form `./.github/workflows/f.yml`) — docs.github.com reuse-workflows; reusable Python test workflow with python-version + test-command inputs — dev.to. Matches python-ci.yml's existing input surface.
- **[pitfalls] (from-source)** python-ci.yml unconditionally runs `pip install -e .` (default install-extras '.') → FAILS in agent-infra (no pyproject.toml). Wiring must pass a non-editable install path, add a stub pyproject, or fix the workflow with a skip-empty guard (which also touches templates/ + sync-ci-workflows.sh materialization).
