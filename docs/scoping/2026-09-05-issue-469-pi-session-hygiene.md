# Scope — #469: idle pi REPL sessions are never reaped

> **Status: SCOPED** — full double diamond + problem-verify + solution-verify + second-model coherence + parallel review gates. Companion research: `docs/research/2026-09-05-issue-469-pi-session-hygiene.md` (findings-date 2026-09-05). Delivered by the project-workflow pipeline for issue #469; scope marker posted on the issue.

## Confirmed Problem

Interactive pi REPL sessions (tty'd, launched in cmux panes) whose work has genuinely finished have **no exit contract**: pi has no idle-exit flag (verified: full `pi --help` + bundle grep clean), cmux `agent-hibernation` cannot serve pi (live `fork_unavailable_reason: pi_version_unverified` blocks restore; count-gated >12 terminals, not age-gated; machine-wide opt-in; kill+cold-restart-on-tab-focus UX), and nothing in agent-infra reaps them — so finished sessions hold RSS indefinitely (live: 22 tty'd REPLs ≈ 3.5–4.0GB; 6 provably idle >24h ≈ 305MB).

**Fix:** a fail-closed, age-gated, org-owned reaper that terminates provably-idle interactive pi REPL sessions while making false-positive reaping structurally impossible and preserving recent-session resumability.

**Evidence-backed corrections to the issue's original framing** (re-derived in the double diamond, not adopted):
- **Indicator-2 (≥2GB drop, <2.5GB typical) is FALSIFIED.** Idle pi RSS is 47–97MB/session (not ~190MB); the morning cohort "13 ≥14h ≈ 2.5GB" was 62% false-positive (8/13 resumed active mid-day — diurnal rhythm, not finished work); reaching ≥2GB would require killing running sessions, violating the issue's own safety rule. Real yield: ~250–400MB/pass (6 candidates ≈305MB at 22:11).
- **Threshold 24h default, not 12h** (12h falsified by the same 62% churn; matches the issue's own Target "0 idle >24h after a pass"). Env-overridable (`REAP_IDLE_HOURS`).
- **Idle semantics: pi session JSONL last-complete-entry** is ground truth (equals cmux `updated_at` to the second for file-backed sessions — both track pi activity). Unparseable/absent/empty file → **NOT idle** (fail-closed; no proof → no kill).
- **Resume reality:** cmux pi-restore is broken upstream → post-reap recovery is manual `pi -r`/`--session` (JSONL persists; pi autosaves per entry; sub-threshold sessions untouched — Indicator 3 intact).

## Idle semantics

- **Idle = now − timestamp of the last parseable JSONL entry** in `~/.pi/agent/sessions/--<cwd with /→->-->/<startedAt>_<sessionId>.jsonl` (reverse-scan for the last complete line; giant tool-result lines up to ~149KB handled; trailing partial write → previous parseable line; type-defensive timestamps — ms `.228Z` and `+00:00` variants).
- **Fail-closed:** unparseable / absent / empty / missing file → not idle, never reaped.
- **Hard gates (ALLOWLIST, per pid, union rule):** reap only when `agentLifecycle == idle` AND `runtimeStatus == idle` on **EVERY** cmux record matching the pid/incarnation; any non-idle twin vetoes (verified: 75–76 pids hold ≥2 records incl. identical-`pidStartSeconds` idle+running twins e.g. 36849). Never-kill vocabulary: running, needsInput, unknown, `error`, None/absent (runtimeStatus real distribution: idle 2966/error 436/needsInput 47/running 19/None 207 of 3,675).
- **Orchestrating-marathon skip:** before kill, walk the target's full recursive descendant tree (ps ppid walk; **live = non-zombie, STAT != Z**): if any live descendant is a `pi` process (e.g. a `task`-dispatched subagent marathon child writing its own JSONL), **skip** — the session is orchestrating, not idle. A skipped parent is re-reapable on a later pass once the descendant exits. A permanently hung pi descendant of a live parent is a documented residual (neither this issue nor #385's orphan sweep reaps children of live parents — manual cleanup; policy doc out-of-scope list). (Closes the S1 gap: pi's SIGTERM trap calls `killTrackedDetachedChildren()`; killing a marathon parent would kill in-flight child work.)
- **Own-session veto (disjunction):** candidate shares tty-of-$$ OR pid ∈ ancestors-of-$$ OR session_id == `$PI_SESSION_ID`. Under launchd (no tty, env absent) the veto is vacuous-correct — no own session exists.
- **Join order:** session_id → JSONL existence + last-entry FIRST, pid pairing second, with **incarnation fence** `pidStartSeconds` ±3s vs ps `lstart` (a stale record's old idle age must never apply to a young live pid).
- **Settle re-verify before every signal** performs a **FRESH per-candidate `${PS_BIN}` probe** of the target pid (never the pass-start snapshot — a static table cannot observe pid-reuse) re-resolving pid → current incarnation (ps lstart), plus JSONL last-entry unchanged since classification (no activity during the pass) + still not self/ancestor.

## Mechanism

**Winner A** (of A standalone-bash-reaper / B extend-#385 / C cmux-config / D python3-file — see Rejected): standalone farmed bash reaper `scripts/pi-reap-idle.sh` + launchd plist `com.eldato.pi-session-reaper` (StartInterval 3600), 4 passes (ps tty'd-pi enumeration → cmux store index → join+veto+fence+idle-age → kill).

- **Kill:** SIGTERM → grace (`REAP_GRACE_SECONDS`, default 5) → SIGKILL, via **`${KILL_BIN:-/bin/kill}` — never the bare bash `kill` builtin** (builtin shadows PATH; e2e shims must intercept every signal). Group-kill (`-pgid`) when pgid==pid (live-verified for all tty'd REPLs — captures MCP children, no new orphans). **pgid≠pid fallback (specified):** per-pid TERM/KILL only, with the orphaned-children risk (children reparent to init — they are the pre-existing state and were already outside the REPL's pgid) documented in the policy doc as an accepted limitation for non-leader environments (SSH-tmux nesting, backgrounded REPLs, future shapes) — never skip the class silently. SIGTERM-primary over cmux `send /exit` because the socket path is unverified under launchd + surface targeting is ambiguous across 1:many records; `/exit` documented as a future enhancement when the socket path is verified. **Real-signal integrity test** (SIGTERM one sacrificial 24h+ candidate, verify JSONL integrity + `pi -r` resume) gates fleet enablement; pi's graceful SIGTERM shutdown is version-sensitive (0.84.3+ verified; note in policy doc).
- **Carrier:** launchd hourly (deterministic cadence; `~/.pi` + `~/.cmuxterm` are TCC-safe — NOT the `~/Documents` wall that retired #432 jobs; `com.tortoise.embedded-reaper` proves a launchd kill-job runs on this box today, disjoint targets: redislite orphans only). Extensions can't host (run only while a pi session is live — the reaper's whole job is killing non-live sessions).
- **Dry-run default for interactive/one-shot; launchd explicitly armed:** interactive default `REAP_DRY_RUN=1` (warn-first, family convention); the plist sets `REAP_DRY_RUN=0` via EnvironmentVariables — and install-launchd.test.sh asserts the rendered plist contains `REAP_DRY_RUN=0` + StartInterval 3600 (no silent disarmed-job mis-render).
- **Single-instance:** portable **mkdir-based lock** — `~/.pi/agent/state/pi-reap-idle.lock` (TCC-safe tree, not /tmp), mkdir = acquired, owner-pid file inside (pid + start epoch), stale rule: owner dead via `kill -0` → break immediately; else lock age > `REAP_LOCK_STALE_SECONDS` (default 1800) → break (session-checks.ts mtime-stale takeover precedent). One-shot `--apply` takes the same lock. `flock` does NOT exist on macOS (util-linux; CI ubuntu HAS it — a platform-divergence trap; the lock MUST NOT depend on it).
- **Store resolution + corruption:** read the canonical `~/.cmuxterm/pi-hook-sessions.json` (NOT stale `.tmp` crash leftovers — cmux's atomic-write temp files don't match the `*-hook-sessions.json` read glob). Missing/corrupt store → visible ⚠️ line + **fail-closed abort of the reap pass** (never "zero candidates → clean exit 0"); on JSON parse error, retry the read once after ~1s before aborting (transient-rewrite flap guard — cmux rewrites mid-operation; atomic-rename assumed, verify during the lifecycle-observation step).
- **Clock seam:** `REAP_NOW_EPOCH` (default `date +%s`) consumed by all age/fence computations — hermetic boundary tests (idle == exactly 24h survives — **threshold comparison is strict `>`**: 23:59:59 not idle, exactly 86400s not idle, 24:00:01 idle; fence ±3s).
- **Bash 3.2-safe only** (macOS `/bin/bash` = 3.2.57): no `declare -A`/`mapfile`/`readarray`/`${var,,}` (family discipline; CI ubuntu bash 5.x would mask 4-only constructs; `bash -n` never executes).
- **Per-pass log + honest measurement:** every candidate logged (pid, tty, rss at kill, sessionId, jsonl, idle_h, action + skip reason); **yield = Σ per-target-pid RSS at kill** (not fleet-wide delta — noise with concurrent activity); pre/post tty'd-pi count + post-pass residual check — **PRE from the pass-start table; POST + RESIDUAL from a FRESH post-pass full `${PS_BIN}` read (killed pids are absent from that read → RESIDUAL=0 after a clean armed pass by construction; a dry-run kills nothing → RESIDUAL = the would-be-reaped count, KILLED=0)** (**RESIDUAL = post-pass re-classification of the reap-eligible set — the SAME gates as the kill pass (JSONL-idle>threshold AND no vetoes); legitimately-skipped >24h candidates (marathon-orchestrating, running-twin veto, own-session) are NOT provably idle and must NOT appear in RESIDUAL; 0 after a good armed pass feeds the 0-provably-idle>24h target**). **Log contract (S2 legibility):** every pass writes a footer `MODE=<dry-run|apply> NOW=<epoch> THRESHOLD=<idle_h> CANDIDATES=<n> PRE=<n> POST=<n> RESIDUAL=<n> KILLED=<n> YIELD=<rss>`; dry-run mode also emits a prominent `DRY-RUN — no signals sent` warning line (an armed pass with zero idle candidates must be distinguishable from a disarmed pass). Log size-guarded (keep last ~200 lines / truncate). Exit 0 on completed passes (degradation = ⚠️ lines).
- **Farmed copy (#427 TCC):** plist points at `{{HOME}}/.pi/agent/scripts/pi-reap-idle.sh`; added to `pi-bootstrap/setup.sh` farm (fleet_srcs list re-commented to "launchd-invoked scripts farm (fleet cadence + pi session reaper)"); setup.sh farm list ↔ install-launchd.test.sh `mkfakehome` list are lockstep (both updated). **Retirement rule** documented (per setup.sh header + agent #1): renaming/removing a farmed script must also retire its plist — broken-target guard can't catch a stale extra.

## Resumability window + policy

- Threshold **24h** (env `REAP_IDLE_HOURS`); cadence hourly → no provably-idle session exceeds ~25h. Sessions idle < 24h (incl. yesterday-evening work) always survive a pass.
- Ghost records (3,622+ `pid_exists=no`) are **cmux's by-design restore registry — never deleted by this reaper** (delete → broken resume affordances); registry/disk hoard (1.06GB workstream.jsonl, stale .tmp, 3.7k-record growth) → **follow-up issue**.
- Headless `pi -p` subagents: out of scope (#385 dispatch-orphan sweeps + watchdog latches own that class; no orphan evidence for reaping live children).
- Session JSONL files are never touched (resume substrate for `pi -r`; #373 fleet-cost cadence + postmortems read them).
