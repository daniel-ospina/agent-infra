## Problem statement

Every reaping path for dispatched pi work (task sub-agents, subagent-tool children, their MCP
grandchildren) executes inside the parent pi's process and event loop. A SIGKILLed parent (Jetsam or
any cause) voids all of them — the parent-side settle-path sweep (`process-sweep.ts`),
`treeKill`, the 6h hard-cap timer, and mcp-client's `process.on("exit")` transport kill all die with
the parent — and surviving process trees reparent to PID 1 where they accumulate. Orphan cleanup
must therefore be **parent-independent**: the orphan detects its own existence via `process.ppid → 1`
and self-terminates by killing its own descendant tree (MCP grandchildren) before exit. A
warn-first session-start sweep (dry-run default, `--apply` manual gate) is the bridge for
pre-existing orphans. Wedged-parent-while-alive and swarm_daemon workers are declared follow-ups
(out of scope).

## Chosen solution — Approach A: ppid watchdog integrated into `extensions/task-heartbeat.ts`

The existing child-side lifecycle extension (already shipped to every print-mode dispatch child in
the global extension set) grows a self-termination arm. The single activation gate is split into
two independent gates; the watchdog runs at **module-load scope** (not `session_start` scope) so a
child wedged before the session starts still self-terminates.

### Mechanism decisions (controller-binding, re-verified against this checkout)

1. **Chosen architecture: A.** `task-heartbeat.ts` is the designated child-side extension shipped
   to every print-mode dispatch child; adding a second child-side extension (B) creates two
   lifecycle concerns + a new global-set file + manifest entry for ~30 lines; C (registry +
   external sweeper) is the architecture-veto approach (no in-child code, highest effort, and does
   not implement the confirmed problem's mandated self-termination mechanism).
2. **Watchdog gate** — `orphanWatchdogActive(env)`:
   `env.TASK_HEARTBEAT === "1" && env.PI_MODE === "print" && env.ORPHAN_WATCHDOG !== "0"`.
   The identity pair `TASK_HEARTBEAT=1 ∧ PI_MODE=print` is the repo's established sub-agent
   signature (verified: `verification-gate/index.ts` `isTaskSubAgent`, drift-guarded in
   `review-enforcer/index.ts:54`). It is **DISABLE-agnostic** (both arming dispatchers carry
   `TASK_HEARTBEAT_DISABLE` only to silence the emitter). This arms for class 1 (task-tool children:
   pair + nonce) and class 2 (subagent-extension children: pair + DISABLE=1) and **EXEMPTS** class 3
   (swarm_daemon workers: `PI_MODE=print` only) and user one-shot `pi -p` runs (pi never sets
   `PI_MODE`; `TASK_HEARTBEAT` is not ambient) — resolving the class-3 question in the safe
   direction: the swarm subsystem owns its own lifecycle (its spawn site is NOT in this repo — only
   comment references exist), so the watchdog never arms in a class we cannot control or verify.
   `ORPHAN_WATCHDOG=0` is the farm-wide opt-out valve (ANDed into the predicate — see FLAW-3).
   **Coverage-change note (diverge→converge):** the diverge's Approach A scored class 3 as
   "covered" (`PI_MODE=print` gate); converge deliberately changes it to "exempt" per the
   confirmed problem's out-of-scope declaration — surfaced here so the delta is ratifiable.
3. **Watchdog mechanics** (module-load scope): capture `originalPpid` + `startedAt` at load; unref'd
   poll (`ORPHAN_WATCHDOG_INTERVAL_MS`, default 15s, zero exec per poll); orphan predicate
   `process.ppid !== originalPpid || process.ppid === 1` (changed-ppid covers Linux subreaper
   adoption; `|| 1` covers the boot race where load-time ppid is already 1); double-confirm (2
   consecutive positive polls); min-uptime guard (`ORPHAN_WATCHDOG_MIN_UPTIME_MS`, default 60s);
   opt-out `ORPHAN_WATCHDOG=0`. Self-termination = kill OWN descendant tree children-first via the
   shared `getChildPids`/`treeKill`, TERM → bounded grace (`ORPHAN_WATCHDOG_GRACE_MS`, default 4s)
   → SIGKILL on survivors, then `process.exit(137)` with an EPIPE-guarded stderr log line. The
   mcp-client `process.on("exit")` transport kill (verified at `extensions/mcp-client/index.ts:347`)
   runs as a second net on `process.exit`. **Self-signal correction — see FLAW-2.**
4. **The sweep bridge** — `scripts/sweep-orphans.sh`: dry-run default; `--apply` manual gate;
   classifier = `ppid==1` AND env `TASK_HEARTBEAT=1` (HARD fail-closed discriminator, **pair-ENV-only**
   — no argv requirement, Phase 7: the argv gate blinded the sweep to MCP grandchildren that inherit
   the pair env; env unreadable → skip, never classify, with a visible ⚠️ line; `ps eww` on macOS /
   `/proc/<pid>/environ` on Linux) AND age cutoff (default 24h, `--cutoff`, `0` disables — the
   settle re-verify is the real settle mechanism) AND settle-window (re-verify `ppid==1` AND the env
   marker immediately before an `--apply` kill); NOT the nonce (subagent children carry no nonce);
   kill primitive on `--apply` = group TERM → grace → KILL **only when `pgid == pid`**, per-pid
   otherwise (a non-detached orphan shares the parent's session group — never group-signal a live
   terminal); ESRCH swallowed; own-pgid REFUSED guard
   (the sweep's own pgid is never a target — protects the orchestrator); per-orphan attribution
   (pid, start time, argv snippet, cwd if obtainable). macOS `ps eww` version-sensitivity caveat
   documented: unreadable env → fail-closed skip (the sweep degrades to fewer candidates, never a
   false positive).
5. **Deploy path — CORRECTED (FLAW-1):** `pi-bootstrap/pi-config/extensions/task-heartbeat.ts` is a
   **symlink** (`-> ../../../extensions/task-heartbeat.ts`), NOT a plain copy — verified by
   `ls -la` and by the #95 drift gate (`scripts/check-pi-config-extensions.sh`, currently green).
   The watchdog change lands in **one** file and propagates via the symlink farm. No dual write.
   Keep the #95 gate green (its check 3 excludes `*.test.ts`, so the new test file needs no
   pi-config entry).
6. **Tests:** `extensions/task-heartbeat.orphan.test.ts` (NEW tsx suite) +
   `scripts/sweep-orphans.test.sh` (NEW bash suite). Append BOTH to `ci-main.yml` — verified: the
   extension accumulator runs exactly 4 tsx suites today (`print-mode`, `print-mode-wiring`,
   `auto-sync`, `sequence-enforcer`) plus an `extensions/*/test*.mjs` glob; bash tests run under
   `script-validate` (`bash -n` + `install-launchd.test.sh`).
7. **Separate issue (NOT absorbed):** `process-sweep.test.ts`, `tree-kill.test.ts`,
   `builtin-tools.test.ts` exist but are NOT in the ci-main accumulator (verified). `builtin-tools.test.ts`
   holds the E14 marker-format drift guard that guards the file this change edits — run it locally

### Rejected alternatives (from Phase 4)

- **B — standalone `extensions/orphan-watchdog.ts`:** rejected at converge. Same mechanism, but a
  new global-set file + manifest entry + a second per-child poll timer, for ~30 lines of logic.
  A's gate split is NOT entangled (verified: the two predicates are independent one-liners and the
  emitter body is untouched), so the stated fallback condition for B does not hold. B's one
  structural advantage (uniform class-3 coverage) is voided by the controller's safe-direction
  decision to exempt class 3 anyway.
- **C — dispatch registry (JSONL at spawn) + external two-pass sweeper (launchd opt-in):**
  architecture-veto approach. Meets the outcome without the confirmed problem's mandated child-side
  self-termination; highest effort (2 spawn-site writes + shared helper + two-pass sweep + launchd
  template + wiring); its honest residuals are a best-effort registry that can miss lines (the
  write is failure-silent and non-awaiting by C's own spec — not a dispatch-path failure mode)
  backstopped by the argv pass, plus an out-of-process kill surface. C's one genuine advantage —
  wedged-proof reaping independent of the orphan's event loop — is real but unrated against the
  acceptance (O1 measures the watchdog path; a sync-blocked orphan is a rare event-loop child
  class). Retained ideas: the sweep bridge, the fail-closed env classifier, and the launchd
  continuous-mode machinery (follow-up 5).
- **Bridge-scope narrowing (diverge→converge, deliberate):** the diverge's shared-bridge spec was
  "argv+ppid classification"; converge tightened it to env+argv (the `TASK_HEARTBEAT=1` hard gate)
  to fail closed against user one-shots and daemons (Phase 7 further dropped argv — the final
  classifier is pair-ENV-only, see Step 3 header (b)). Interactive `pi -p` orphans without the pair
  env are a declared residual (see coverage matrix row 9 + Step 3 header docs).

### Controller-verified facts the plan relies on

- `process.ppid` updates to 1 after reparenting on macOS (live-verified in Phase 1–3).
- Both dispatchers spawn **detached** (`setsid` → own pgid/session) with
  `stdio:["ignore","pipe","pipe"]`; stdin is ignored, so no stdin-EOF signal exists for the child.
- `default()` of `task-heartbeat.ts` runs at extension registration (startup), before
  `session_start` — module-load scope is achievable by restructuring the early return.
- Sub-agent argv is `pi -p …` or `node <entry> -p …` in both dispatchers.
- The child is alive when the watchdog fires → its descendants are still attached → the PPID walk
  (`getChildPids`) works (children only reparent when the child itself dies).

## Validation corrections (Phase-5 findings — all code-verified)

- **FLAW-1 (decision 5, genuine — VERIFIED):** `pi-bootstrap/pi-config/extensions/task-heartbeat.ts`
  is a symlink into `extensions/`, enforced by the #95 drift gate. The controller's "IDENTICAL
  PLAIN COPIES — must land in BOTH" is factually wrong. **Fix:** single-file edit; run
  `check-pi-config-extensions.sh` to confirm the farm stays green. Deploy path simplified.
- **FLAW-2 (decision 3, genuine implementation hazard):** `treeKill(process.pid, "SIGTERM")` sends
  SIGTERM to **self** as its final step (tree-kill kills the target pid after its children), which
  would terminate the watchdog process itself (exit 143) before the TERM→grace→KILL escalation and
  before `process.exit(137)`. **Fix:** never signal self. Fire sequence = `getChildPids(process.pid)`
  → `treeKill(childPid, "SIGTERM")` per **direct** child (treeKill recurses children-first within
  each subtree → MCP grandchildren and bash forks die) → ref'd grace sleep → re-walk direct children
  → `treeKill(childPid, "SIGKILL")` on survivors → `process.exit(137)`. Reuses shared primitives
  unchanged; adds only the orchestration.
- **FLAW-3 (decision 2/3 wording, minor):** the `ORPHAN_WATCHDOG=0` valve must be ANDed into the
  gate predicate itself (single site), not applied as a separate arming check — avoids a second
  place to get the gate wrong. Specified above.
- **Note (class 3 consequence, documented not corrected):** the identity-pair gate exempts swarm
  workers from the watchdog AND the sweep's `TASK_HEARTBEAT=1` env hard gate also excludes them
  (env lacks the pair) — class 3 is a declared residual in both mechanisms, consistent with "the
  swarm subsystem owns its own lifecycle". A future swarm-side change can opt in by setting the
  pair or its own watchdog; no action here.

## Implementation steps (bite-sized, ordered)

### Step 1 — `extensions/task-heartbeat.ts`: gate split + watchdog arm (single-file edit)

a. **Export `orphanWatchdogActive(env)`** — predicate per decision 2 (identity pair, DISABLE-
   agnostic, `ORPHAN_WATCHDOG !== "0"` valve). Pure; env-param seam (mirrors `taskHeartbeatActive`).

b. **Export `isOrphaned(ppid, originalPpid)`** — pure predicate:
   `ppid !== originalPpid || ppid === 1` (subreaper arm + boot-race arm). No env/process reads.

c. **Injectable seams for tests** (process-sweep.test.ts injectable-hook precedent): a module-level
   `ppidGetter` (default `() => process.ppid`), `nowGetter` (default `Date.now`), `killDescendants`
   hook (default = the shared getChildPids/treeKill orchestration from FLAW-2), and an `exitProcess`
   hook (default `process.exit`). Honor the repo's #212 security-pass convention: overrides apply
   only under `NODE_ENV=test` (review-enforcer `_setRunGhOverride` precedent). Keep the seams tiny
   and documented; runtime callers use defaults.

d. **Restructure `default(pi)`:** compute `watchdogActive = orphanWatchdogActive()` and
   `emitterActive = taskHeartbeatActive()`; `if (!watchdogActive && !emitterActive) return;`
   → arm the watchdog when `watchdogActive` → `if (!emitterActive) return;` → existing emitter body
   untouched. **`armOrphanWatchdog()` returns `{ timer, poll }`** (testability: the suite asserts
   `timer.hasRef() === false` and drives `poll()` synchronously) and guards against double-arm
   with a module-level `alreadyArmed` flag (pi's loader re-runs the factory on `ctx.reload()`).
   The arm is a **module-load-scoped** side effect: capture `originalPpid` and `startedAt` at arm
   time; `setInterval(poll, getOrphanIntervalMs())` with `timer.unref?.()`.

e. **Poll body:** every tick compute `currentPpid`; maintain a consecutive-positive counter;
   reset on a negative poll. Fire only when `isOrphaned(currentPpid, originalPpid)` is true for 2
   consecutive polls AND `now - startedAt >= getOrphanMinUptimeMs()`.

f. **Fire sequence (FLAW-2 + pgid catch-net, exception-proof):** EPIPE-guarded stderr line
   `[task-heartbeat] orphan_watchdog parent=<orig> ppid=<cur> uptime_ms=<n> — self-terminating`
   (reuse the existing try/catch `emit` pattern — note: stderr EPIPE to a dead parent surfaces as
   a silenced async `'error'` event, not a try/catch catchable exception; Node swallows it by
   default — live-verified, the emit pattern is safe as-is);
   **durable attribution** — best-effort append to `~/.pi/agent/orphan-watchdog.log`
   (pid, parent, ppid, uptime, timestamp; EPIPE-safe, never throws — the forensic record for
   killed-mid-write MCP state, extending the #195 partial-state hygiene note to this kill
   surface);
   kill direct children TERM (walk → `treeKill(child, "SIGTERM")`); ref'd grace sleep
   (`ORPHAN_WATCHDOG_GRACE_MS`, default 4_000, floor 1_000 — must NOT be unref'd: we must stay
   alive to finish the kill); re-walk direct children → SIGKILL survivors; **final pgid catch-net**
   — when the child is its own pgid leader (`getPgid(process.pid) === process.pid`, the detached
   spawn case): `pgrep -g <ownPgid>` and SIGKILL any survivor other than self (closes the
   mid-fork escape — a descendant forked between re-walk and exit); then `exitProcess(137)`.
   The whole sequence runs inside try/finally — the pgid catch-net and `exit(137)` ALWAYS run
   even if an unanticipated exception occurs mid-sequence.
   The mcp-client exit handler fires synchronously on `process.exit` as the second net.
   **Fired latch:** set a `fired` flag at sequence start; the poll checks it first and never
   re-fires (a concurrent poll tick mid-grace must not start a second sequence); the grace sleep
   is a ref'd `setTimeout` (async, awaitable — the event loop is alive and we are exiting anyway).

g. **Constants:** `ORPHAN_WATCHDOG_INTERVAL_MS` (default 15_000, floor 5_000),
   `ORPHAN_WATCHDOG_MIN_UPTIME_MS` (default 60_000), `ORPHAN_WATCHDOG_GRACE_MS` (default 4_000),
   `ORPHAN_WATCHDOG` (opt-out). All read via getters with clamp-to-floor semantics (house pattern:
   `clampHeartbeatIntervalMs`).

h. **Docs:** update the file header and the #285 comment block — `TASK_HEARTBEAT_DISABLE=1`
   disables the **emitter only**; the watchdog is DISABLE-agnostic and self-terminates an orphaned
   child on every farm (tortoise/eldato inherit). Mitigations: min-uptime + double-confirm +
   `ORPHAN_WATCHDOG=0` valve.

### Step 3 — `scripts/sweep-orphans.sh` (NEW; scan-orphans.sh pattern verbatim in structure)

> **Header docs (required content):** (a) Linux subreaper gap — pre-existing orphans adopted by a
> non-1 subreaper (systemd user scope, PR_SET_CHILD_SUBREAPER, supervising container init) are NOT
> classified by the `ppid==1` gate; the watchdog's changed-ppid arm covers NEW orphans on Linux,
> subreaper-class sweep is a declared follow-up; (b) the classifier is **pair-ENV-only** (Phase 7
> review: the argv gate's protective value ≈ 0 — ambient-pair one-shots carry `-p` and are
> classified regardless; the only thing it excluded was MCP servers, which inherit the pair env via
> `buildMcpServerEnv`'s `process.env` spread (mcp-client/index.ts:146) — the Jetsam-burst recurrence
> class this issue exists for. Dropping argv makes the sweep catch dispatch children AND their MCP
> grandchildren; interactive `pi -p` one-shots without the pair env remain excluded (residual,
> consistent with the "pi sub-agent processes" indicator scope); (c) the env gate's macOS
> `ps eww` readability is version-sensitive — verified empirically on macOS 25.5.0 (same-user env
> visible), unreadable → fail-closed skip with a visible ⚠️ line; (d) etime is suspend-insensitive
> on both platforms (kernel ticks pause during sleep) — a machine suspended past the cutoff keeps
> an orphan's etime small; the in-child watchdog is wall-clock (Date.now) and still reaps it — the
> divergence is documented, not a bug; (e) the sweep honors the same `ORPHAN_WATCHDOG=0` valve as
> the watchdog — pair-env farms that opt out must not be swept (skip + visible ⚠️).

- Flags: `--apply` (manual kill gate), `--cutoff N` (hours, default 24; **`0` disables the age
  gate** — test/settle override; the settle re-verify is the real settle mechanism), `--help`.
  Dry-run default.
- **Classification** (per process from `ps axww -o pid=,ppid=,pgid=,stat=,etime=,command=`):
  1. `ppid == 1` (fail-open to "not orphan" otherwise);
  2. **state Z (zombie) → SKIP** — a defunct process holds no memory and cannot be killed
     meaningfully; explicit skip keeps the count honest (the env gate would exclude it anyway
     once its memory is freed);
  3. env read: `ps eww -p <pid>` (macOS) or `/proc/<pid>/environ` (Linux) → must contain the
     EXACT token `TASK_HEARTBEAT=1` (word-boundary match after whitespace/NUL split — a
     substring match would false-positive on `TASK_HEARTBEAT=10`) — **hard gate, env-only**: no
     argv requirement (Phase 7: see header (b)); `ORPHAN_WATCHDOG=0` in the env → SKIP with a
     visible ⚠️ line (opt-out valve parity with the watchdog); unreadable/empty env → SKIP
     (fail-closed, never classify) + visible `⚠️ env unreadable for pid N — skipped, cannot
     classify` line — a degraded classifier (macOS version-sensitivity, cross-user) is never
     silent: the warn-first contract fails visibly, not silently;
  4. age ≥ cutoff (from `etime` — elapsed time, same `D-HH:MM:SS`/`HH:MM:SS` format on macOS and
     Linux — macOS verified: `06-21:35:06` for a 6-day process, `00:00` for young; a ~5-line
     duration→seconds parser handles `[D-]HH:MM:SS` / `MM:SS` on BOTH platforms; the 24h default
     is pure conservatism protecting daemon-shaped processes — the env gate already excludes
     non-dispatch processes, so the cutoff is not the settle mechanism); settle-window: `--apply`
     re-verifies `ppid==1` AND the env marker immediately before each kill (pid-recycling
     insurance — a recycled pid with a coincidental ppid==1 must never be killed); settle
     re-verify FAILURE (pid gone / env unreadable) → SKIP with a ⚠️ line, never kill on
     ambiguous state;
  5. own-pgid REFUSED: `ps -o pgid= -p $$` — an orphan's pgid equal to the sweep's own pgid is
     skipped with a warning (protects the orchestrator running the sweep).
- **Kill primitive (group-composition safe — Phase 7 P1):** group-kill (`kill -TERM -- -<pgid>`
  → grace → `kill -KILL -- -<pgid>`) ONLY when `pgid == pid` (the detached/leader case — the
  group contains only the orphan + its descendants). When `pgid != pid` (a non-detached spawn,
  `TASK_DETACHED=0`/`SUBAGENT_DETACHED=0`, shares the parent's session group — a negative-pgid
  kill would take out a LIVE terminal) → per-pid TERM → grace → KILL with the settle re-verify
  per pid, NEVER a group signal. Dead-group ESRCH → explicit `|| true`/`2>/dev/null` (the bash
  builtin returns exit 1 on a dead group).
- **Whole-run degradation visibility:** if the classifier itself cannot run (ps missing, exec
  timeout, unsupported flags), emit `⚠️ <tool> unavailable — sweep degraded, no classification
  performed` and still exit 0 — a degraded sweep must be loud, never silently no-op (asserted in
  the bash suite).
- **Per-orphan attribution:** pid, elapsed time, pgid, argv snippet (truncated), cwd when
  obtainable (`lsof -a -p <pid> -d cwd` best-effort, silent fail).
- **Warning-line contract:** every classified orphan emits a stable marker line starting with `🧹`
  (scan-orphans style) — the auto-sync filter depends on the token; asserted in the bash suite.
- Exit 0 always (warn-only surface; failures are attribution notes, never a hard error).

## Verification plan (acceptance criteria mapped to O/I/T)

**O1 — No orphaned dispatched pi processes (incl. their MCP grandchildren) after a Jetsam-class parent kill.**
- I1: < 2 orphaned processes with `ppid==1` + pair env (**regardless of argv** — incl. MCP
  grandchildren, **stat != Z**) within
  min-uptime + 2×interval + grace (≤ ~95s from spawn; ≤ ~40s post-kill when the harness pre-waits
  ≥65s to satisfy the 60s min-uptime floor) after a simulated kill. Count includes MCP
  grandchildren (pair env inherited — the Jetsam-burst recurrence class).
- T1: manual harness (verification script or ad-hoc): spawn a task-style child (identity pair env +
  `-p` argv) that holds an MCP-server grandchild; **wait ≥65s** (min-uptime satisfied); SIGKILL the
  parent (`kill -9`); poll `ps -axo pid=,ppid=,stat=,command=` (exclude state Z) for the child pid
  and the MCP pid. Both must be gone within ~2× interval + grace (~40s) after the kill. Run 3×
  (task class), 3× (subagent class, DISABLE=1). **Young-child case:** also run once killing the
  parent at ~10s child uptime — the child must self-terminate ≤ ~95s from spawn (uptime floor +
  polls + grace); asserts the I1 bound covers young orphans, not just the pre-waited harness.

**O2 — Pre-existing orphans don't accumulate silently.**
- I2: session-start sweep runs warn-only (dry-run) every session; pre-existing orphans surface.
- T2: sweep unit-tested in dry-run (bash suite: dry-run lists, `--apply` refuses-by-default);
  auto-sync wiring verified (warn-only, bounded timeout, silent on missing script).
- **Required macOS verification (promoted from "manual item" — the env gate is the classifier's
  linchpin on the PRIMARY platform):** the bash suite MUST be run locally on macOS (commit gate),
  exercising the `ps eww` env branch against real reparented orphans; the research artifact
  records the empirical verification (macOS 25.5.0: same-user `ps eww -p` surfaces
  `TASK_HEARTBEAT=1`/`PI_MODE=print`). A macOS where `ps eww` returns no env → the sweep
  degrades visibly (⚠️ lines) and the bridge's reach is documented as env-unreadable.

**O3 — RSS bounded.**
- I3: no monotonic RSS growth across repeated parent kills.
- T3: **re-baselined as a trend** — reaping alone cannot reach the original 1.5GB target per the
  RSS math (accumulated pi processes are only part of the resident footprint; the 1.5GB figure
  also includes caches/farm overhead outside this issue's reaping surface). Acceptance: after 5
  consecutive kill→wait cycles, the count of orphaned task-shaped processes stays < 2 (O1) and RSS
  of the surviving processes does not grow monotonically across cycles. The 1.5GB target is
  re-baselined in the issue as a trend metric owned by the follow-up swarm/wedge work.
