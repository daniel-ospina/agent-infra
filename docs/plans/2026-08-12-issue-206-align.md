## Stage 1 — Align (standalone, adversarial-lite)

**Context observed during Align:** this alignment run itself was a nested
print-mode pi under the sequence-enforcer gate, whose gate extensions blocked
this session's bash, write, task, and subagent tools at the research/scope
steps — a live, mild instance of the exact interference class the issue
targets (see #201/#202). The bounded-launch rule would have given this run an
automatic timeout, log redirect, and liveness marker instead of a silently
stalled nested pi. Recorded as first-hand evidence that the failure class is
recurring.

**O/I/T check:**
- Objective — coherent and behavior-framed ("never launch unbounded";
  guard escape = terminal one-liner); directly tied to the observed incident
  (105,150s hang, 2026-08-11→12). ✓
- Indicators 1–3 — all verifiable by grep + source assertion (drift-guard
  pattern from #178: `extensions/shared/test-git-freshness.mjs` precedent).
  Indicator 3 (every nested/background pi example carries the bounded
  pattern) covers drift in skill text. ✓
- Target — measurable: grep of the three skills + `node
  scripts/check-skill-lint.mjs` exit 0. Note: check-skill-lint.mjs
  (scripts/) validates frontmatter (name, description, allowed-tools for
  Bounded/Workflow/Routing), name↔dir match, dup keys, forbidden
  "sequential or parallel" — it is a regression guard for the rule text,
  not a rule checker; the grep target is the rule's real verification.
- **Gaps flagged (fold at Scope/Plan):**
  1. Indicator 1's premise is currently FALSE: grep of the live local copy
     (~/.pi/agent/skills/using-git-worktrees/SKILL.md) shows NO `git checkout

     guard-escape wording, not reference existing text. (Canonical repo copy
     skills/using-git-worktrees/SKILL.md to be re-verified at Research; my

  2. No acceptance value for the timeout N — define at Scope (suggest

  3. No criterion codifying the abort trigger — "no liveness marker within

     failure as much as a no-timeout failure.

**Eisenhower:** Important + Urgent. The 2026-08-11→12 incident cost ~29h of
fleet wall-clock (105,150s) with zero progress and required a manual abort —
one hang of this class is already a fleet-wide outage. The fix is
documentation-only (3 skill files + lint), cheap to ship, and closes the
launch-side gap that #201/#202 (stall mechanics) do not cover. Same fleet-
health class as #178.

**Adversarial challenge 1 — "A single runbook page would suffice; editing 3
skills is over-engineering."** A standalone runbook page is read once and
lives away from the launch sites. The three target skills are the fleet's
launch/dispatch paths: `using-git-worktrees` (guard-escape context,
main-checkout recovery), `parallel-orchestrator` (bash `&` background
patterns, pre-warming), and `subagent-driven-development` (task/subagent
dispatch, worktree handoff). A rule embedded in the skills agents load at
launch time is enforced at the point of failure; skill edits are also the
repo's only enforced-doc mechanism (check-skill-lint + drift gate) — a
runbook gets no such enforcement. A one-line cross-reference from a runbook
is optional, not a substitute. PROCEED.

**Adversarial challenge 2 — "Agents won't read the rule anyway; it will be
cargo-culted into unbounded launches regardless."** Partially true: a
documented rule cannot physically bound a launch — this is a procedural, not
enforcement, control. But the issue's own framing is modest: it codifies the
sanctioned pattern (timeout + log redirect + liveness marker) and designates
the terminal one-liner as the ONLY guard escape, removing the ambiguity that
kept the 2026-08-11 operator waiting 29h before aborting. Mitigation folded
in: the rule MUST also state the abort fallback (no liveness marker within N
→ abort immediately — never wait indefinitely), which makes the bounded
pattern self-checking even for agents that merely copy it. Verifiable Targets
(grep + lint) make the rule auditable post-hoc.

**Align decision:** GO — documentation-only 3-skill change, lint-gated,
verifiable by grep. Two risk-lowering folds are plan-stage details, not
blockers: (1) ADD the terminal one-liner + guard-escape wording where absent;
(2) codify timeout value N and the no-liveness-marker abort trigger.
