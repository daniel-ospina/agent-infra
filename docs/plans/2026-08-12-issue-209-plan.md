## Confirmed problem

Under load storms (bgsave/build/git bursts), static watchdog bounds cut live sub-agents and unconditional batch scripts compound the load — with no load sensing, no env-overridable shell-out timeout pattern, and no suspension policy anywhere in the fleet:

1. **Structural #198 gap (code-provable, recurred live twice on 2026-08-12):** the first-message clause (`heartbeatKillDecision`, extensions/builtin-tools/index.ts:785–798) never checks `toolsInFlight` (the silence clause at 774–780 does). `parseHeartbeatLine` latches `turnSawTool` only from tick `saw_tool` (index.ts:581), not from `tool_start` (548–550), so a tool in flight with a lost/pre-tick `saw_tool` is cut at 300s instead of at the 6h tool-stall bound L. `E13` never sets `toolsInFlight`, so the gap is untested.
2. **No load gating anywhere:** zero `loadavg`/`os.loadavg()` references in agent-infra. scripts/daily-backup.sh triggers the storm-causing BGSAVE unconditionally; scripts/cron-quality-gates.sh runs unconditionally; no suspend/resume policy exists.
3. **#196 class:** no shell-out timeout in the tree is env-overridable except the `TASK_*` watchdog family — slack-bridge still hardcodes the 2s git cap (index.ts:963) that flaked in #196; tree-kill hardcodes 2s (shared/tree-kill.ts:18).

**Falsification test (matches E13b exactly — copyable verbatim, RED on today's code):** `heartbeatKillDecision(dinput({ state: st }))` with `st.turnActive = true`, `st.turnSawMessage = false`, `st.lastMarkerAt` fresh, `st.toolsInFlight = 1`, `st.turnSawTool = false`, `st.streamAgeMs > M` → `{ kill: true }` with reason `first-message-stall` (a live tool being cut). Note `createHeartbeatState()` defaults (`turnActive:false`, `lastMarkerAt:0`) would return kill:false — the test must set them explicitly. If this returned no-kill today, the watchdog half would reduce to a threshold tweak; it does not.

### Task 1: Watchdog half — first-message exemption + load-scaled latched bound (A1)

**Intent:** Never cut a live tool; scale the first-message bound with 1-min loadavg so storms extend (never shrink) the effective bound; make bound extension observable in production without a kill.

**Acceptance:**
- `HeartbeatDecisionInput` gains: `load1?: number` (default 0), `loadScaleStart?`, `loadScaleMax?`, `loadSuspendThreshold?` (defaults derived per-core so tests are machine-independent), `latchedFirstMessageMs?: number` (previous tick's latched effective bound; undefined = first tick).
- First-message clause gains `st.toolsInFlight === 0` — with `toolsInFlight > 0` the clause never fires (live tool bounded by the tool-stall clause at L=6h, precedence #1). Deliberate behavior change, pinned by E13b.
- `scaleFirstMessageMs(baseMs, load1, cfg)` — pure: `baseMs` when `load1 ≤ start`; `round(baseMs × max)` when `load1 ≥ suspend`; linear mid-band `round(baseMs × (1 + (load1−start)/(suspend−start) × (max−1)))` otherwise; clamped to `[baseMs, baseMs × max]` — load only EXTENDS, cap at 3× (900s). Never NaN/Infinity (config clamp guarantees denominator > 0).
- `getLoad1()` + seam: `let _load1Override: (() => number) | null = null; export function __setGetLoad1(fn) { _load1Override = fn; } export function getLoad1(): number { return _load1Override ? _load1Override() : os.loadavg()[0]; }` (precedent: `__setGhIssueFileImpl` in slack-bridge). Extend the `node:os` import (`homedir` → add `loadavg`, `cpus`).
- Getters: `getLoadScaleStart()` (TASK_LOAD_SCALE_START, default `round(1.5 × os.cpus().length)`), `getLoadScaleMax()` (TASK_LOAD_SCALE_MAX, default 3), `getLoadSuspendThreshold()` (LOAD_SUSPEND_THRESHOLD, default `round(2.5 × os.cpus().length)`), composed by `getLoadScaleConfig()` which applies the ordering clamp (suspend ≤ start → both defaults). `getFirstOutputTimeoutMs()` (TASK_FIRST_OUTPUT_TIMEOUT_MS, default 60s, clamp ≥ 60s) replaces the hardcoded `FIRST_OUTPUT_TIMEOUT_MS` use at index.ts:1164/1215/1250 (constant stays as the default).
- `heartbeatKillDecision`: computes `tickEffM = scaleFirstMessageMs(i.firstMessageMs, load1, cfg)`, `effM = i.latchedFirstMessageMs === undefined ? tickEffM : Math.max(i.latchedFirstMessageMs, tickEffM)` (the monotonic latch), uses `effM` as the first-message bound, and returns an ADDITIVE `firstMessageMs: effM` field so the loop threads the latch. - 10s decision loop (index.ts:1222–1272): keeps `let latchedEffM: number | undefined; let lastLoggedEffM = 0;` per dispatch; each tick passes `load1: getLoad1()`, the scale config, `latchedFirstMessageMs: latchedEffM`; threads `decision.firstMessageMs` back into `latchedEffM`; when `effM > base M` and `effM > lastLoggedEffM`, emits `console.error(`[task] first-message bound ${from}s → ${effM}s (load1=${load1})`)` (e.g. `[task] first-message bound 300s → 900s (load1=60)`) — the existing `[task]`-prefixed convention, naturally rate-limited to bound increases; kill headline (index.ts:1265) shows the EFFECTIVE bound (uses the latched effM, not the base).

### Task 3: Shared load-gate helper (A2)

**Intent:** One pure, env-overridable, CLI-consumable load gate for bash wrappers (and the documented contract for future cross-repo consumers), with hysteresis and a deterministic test path.

**Acceptance:**

Wired at the CLI (F2): plain `check` uses `shouldSuspend`, `check --deferred` uses `shouldResume` (see CLI spec).

- Header comment documents: signal semantics (`os.loadavg()[0]`, 1-min exponential average, I/O-inclusive — sensitive to exactly the BGSAVE-storm class), macOS thread-counting semantics (Darwin counts threads → per-core readings run higher than Linux; spurious SUSPENSION is the safe direction; per-host env thresholds), cgroup/VM-steal blindness (accepted for a same-host fleet), exit-code contract.

## Runtime prerequisites / risks

- **Node ≥ 18** (`os.loadavg()` — ships on both fleet platforms, zero deps). Plain-node runtime for `scripts/load-gate.mjs` (never imports extensions — no TS-loader coupling); extensions run under pi's TS loader as today.
- **bash 3.2+ (macOS)** — no associative arrays in the wrapper changes (existing compat style).
- **Real load never read in tests** — `os.loadavg()` is real host signal; all tests inject (input field / seam / `run()` deps). `LOAD_SUSPEND_THRESHOLD=0`/`999` + `LOAD_GATE_MAX_WAIT_MIN=0` give deterministic wrapper tests without a CI load generator. For daily-backup ONLY the `0`-path is executed in verification — the `999`/force paths would fire a live BGSAVE; they are proved at the helper CLI instead (see Task 4 acceptance, F5).
- **Residual cut class (accepted):** at the 3× cap, a first message that normally takes >90s is still cut after 900s under a persistent storm (10× slowdown ⇒ 900s < 1500s needed). The 6h tool-stall clause remains the backstop for in-flight tools. Uncapped scale would let hung providers linger indefinitely — the cap exists to bound that.
- **macOS loadavg semantics:** Darwin counts threads (idle systems can show load > 1.0; multi-threaded workloads double-count) → per-core readings run higher than Linux; defaults are calibrated to Linux; spurious SUSPENSION is the safe direction (deferrals are loud and resumable); per-host env thresholds documented in the policy doc.
- **cgroup/VM-steal blindness (accepted):** loadavg is host-wide; a quota-capped container can be CPU-starved while loadavg reads low, a neighbor's storm can raise loadavg while this host is idle. Same-host fleet makes this acceptable; documented.
- **Daily-backup invoker unidentified in-repo:** the exit-3 re-invoke contract depends on an external invoker with unknown exit-code handling; if it cannot re-invoke, the contract degrades to loud failure requiring human re-invoke. **RPO ≤ 48h** under sustained deferral (a deferral near one daily invocation can slip to the next) — accepted trade for load safety.
- **Skill-gate residual (doc-only):** the "defer ≠ lose" guarantee for skill-dispatched gates has no enforcement that the gate eventually re-ran — exit-3 surfaces as loud failure; residual acknowledged in the policy doc (F9g).
- **BGSAVE is itself a storm igniter:** the gate defers only under PRE-EXISTING load; once BGSAVE is in flight the script completes its wait (no second-igniter via re-invoke).
- **Out of scope (tracked follow-ups):** `extensions/subagent/index.ts` load-awareness (distinct kill path, already env-overridable, lower dispatch volume — explicit follow-up); swarm `state_machine.py` (CLI contract documented as the handoff); tortoise #1005 root cause (separate repo; #209 is defense-in-depth); remaining 14 hardcoded shell-out caps (incl. slack-bridge `GH_API_TIMEOUT_MS`) — follow-up applying the now-proven getter pattern; load-scaling of the stream-stall/silence/tier-1 clauses.
