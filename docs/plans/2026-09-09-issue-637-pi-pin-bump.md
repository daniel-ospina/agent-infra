# #637 — align pi runtime pins to 0.85.1 — Scope & Plan

## Confirmed Problem

The repo's pi-version alignment is enforced only by **machine-local, partly vacuous tripwires**:

- `scripts/patch-pi-retry.sh --check` cannot detect version drift — `check_oracle_reprobe_precondition`
  is skipped for `--check`/`--paths` by construction, and `--check` only greps two patch-marker lines.
- The loader-parity oracle (`scripts/check-skill-lint.oracle.test.mjs`) is **not wired into CI** at all
  (dev-machine / cron only) — it is the only gate that compares repo state against a real pi bundle.
- The **per-PR path ran no pin check**: `ci.yml` → `node-ci.yml` passed no `test-command`, so the
  unit-test job was skipped. A **cross-file pin assertion did not exist anywhere** before this change —
  the only pin literal was a tautological `assert.equal(PI_VERSION_PIN, "0.84.3")` in
  `check-skill-lint.test.mjs` (its removal is scoped in #643). The suite that now carries the assertion
  ran, and still runs, post-merge in `ci-main.yml`.

Meanwhile `main` pinned pi **0.84.3** while the installed runtime was **0.85.1**, and the hand-synced
mirror class had **already escaped once**: `docs/providers.md` and
`extensions/custom-provider-qwen/index.ts` asserted live verification against pi **0.84.1** (with
version-specific pi-ai line refs `128`/`514`) from `3e08f6f` (2026-08-10) while the canonical pin was
**0.84.3** from `e30d7f7` (2026-08-28) — stale for 12+ days, corrected only opportunistically in
`65bdda6` (line refs → `202`/`577`).

Therefore #637 must (1) align every repo-side pin at 0.85.1, and (2) leave behind at least one
**CI-enforced, non-vacuous** alignment tripwire (the Phase-2 wording, unchanged).

**Status of (2): PARTIALLY MET — the "enforced" half is UNMET, and this is a human decision.** What
shipped is CI-**visible**, not CI-enforced: the tripwire runs on every PR and on `main`, but branch
protection requires only `pipeline-compliance`, so a red `ci / unit-test` does not block a merge. Making
code CI blocking is a repository-governance change outside this chore's authority; it is scoped as
**#646** and surfaced as an unmet criterion below. The structural cures are scoped to **#642**
(CI-detectable drift), **#643** (single source of truth for version state) and **#651** (line-ref
integrity).

## Plan

### Proposed solution

A mechanical pin bump following the documented #254 re-probe workflow
(`probe-frontmatter-fixtures.mjs --write` → review diff → oracle re-verify), **plus** the pin-lockstep
tripwire wired into the per-PR path.

1. **`PI_VERSION_PIN` 0.84.3 → 0.85.1** in `scripts/frontmatter-fixtures.mjs`, regenerated by
   `node scripts/probe-frontmatter-fixtures.mjs --write`. Exactly **2 changed lines**; **zero
   fixture-consequence diffs across 135 fixtures** — the 0.85.1 skill loader is behaviorally identical
   to 0.84.3 for every fixture in the corpus.
2. **6 devDep pins → 0.85.1** across `extensions/{review-enforcer,verification-gate,subagent}/package.json`
   (`@earendil-works/pi-coding-agent`, `pi-ai`, `pi-agent-core`, `pi-tui`), exact pins (never `^`).
3. **3 lockfiles regenerated.** Upstream `@earendil-works/pi-client` and `pi-protocol` are dropped;
   `@earendil-works/chord` is added transitively. Nothing in-repo imports any of the three — the graph
   change is purely transitive. See "Lockfile verification" below.
4. **Mirror corrections** in `.github/workflows/ci-main.yml`, `scripts/frontmatter-validate.mjs`,
   `docs/providers.md`, `extensions/custom-provider-qwen/index.ts`, and the version-neutral rewords in
   `extensions/subagent/{timeout,cache}-integration.test.ts`.
   `docs/upstream-pi-bugs.md`'s historical v0.84.3 probe record is **deliberately preserved** as
   version-stamped history, annotated "re-verified pi v0.85.1 — zero drift".
5. **New pin-lockstep tripwire `(h)`** in `scripts/check-skill-lint.test.mjs`: every
   `@earendil-works/pi-*` pin in `extensions/*/package.json` in any of the six pin-bearing fields
   (`dependencies` / `devDependencies` / `peerDependencies` / `optionalDependencies` / `overrides` /
   `resolutions`) must equal `PI_VERSION_PIN`, and the per-extension pin count must match the expected
   map (a bare zero-match check passed when coverage silently collapsed — see item 7). **Bound:** it
   reads the direct `extensions/*/package.json` manifests only — nested and repo-root manifests are not
   walked (→ #643).
6. **Per-PR wiring (fix round; also review gate #2 P1 / gate #4 P0).** `.github/workflows/ci.yml` passes
   `test-command: node scripts/check-skill-lint.test.mjs` to its `node-ci.yml` call, so a partial pin
   bump **reports on the PR that introduces it** rather than only in `ci-main` after merge. The suite is
   node-stdlib-only (no `npm ci`, no extension devDeps): ~4s of work plus one `ubuntu-latest` runner per
   PR — the repo's only per-PR pin check. It also promotes the rest of the frontmatter suite (fixtures,
   the live `skills/` corpus sweep and the CLI-exercising cases — see the Testing-strategy table) onto
   the PR path; that overlap with the existing per-PR `ci / skill-lint` job is accepted deliberately
   (distinct red signals are not separable without splitting the suite — see Rejected Alternative F).
   **Rework trigger:** extract the pin guards into a single-purpose job when #646 makes the PR path
   blocking, or when the suite grows.
   ⚠️ **This makes the check CI-*visible* per-PR, not merge-blocking.** Branch protection on `main`
   requires exactly one context, `pipeline-compliance` (process evidence only — its own header says it
   "checks process evidence, not code quality", and it never reads other jobs' results), so **every**
   job in `ci.yml` is advisory today. Making code CI blocking is a repo-governance change scoped as
   **#646**; the honest claim for this change is "reported on the PR", not "enforced".

7. **Three follow-on guards added in review cycle 2** (closing "the tripwire guards the wrong class",
   "the non-vacuity guard is too weak" and "the wiring can silently unplug"):
   - **`(i)` mirror version stamps** — every `<major>.<minor>.<patch>` literal in the four hand-synced
     mirror surfaces (`docs/providers.md`, `extensions/custom-provider-qwen/index.ts`,
     `scripts/frontmatter-validate.mjs`, `.github/workflows/ci-main.yml`) is either `PI_VERSION_PIN` or an
     explicitly allowed non-pi dependency version (yaml `2.9.0`, undici `8.9.0`), with a per-surface
     stamp-**count** map (`{providers.md: 1, qwen: 1, frontmatter-validate.mjs: 3, ci-main.yml: 2}`) so
     a lost surface **or** a dropped stamp is red (the first attempt — a `>= 1 per surface` presence
     check — stayed green when a surface lost one of three). **This is the
     class that actually escaped on 2026-08-10.** Accepted residuals: the allowlist is keyed by version
     string (not occurrence) and only 3-component literals are scanned.
   - **`(j)` per-PR wiring self-check** — asserts `ci.yml` still triggers on `pull_request` with no
     `paths`/`paths-ignore`/`branches` filter (the outermost bypass: `paths-ignore: ['extensions/**']`
     skips the whole run for exactly the PRs the gate guards, and the job block is never evaluated),
     that it self-calls `node-ci.yml@main` (the ref is a locked decision D2, not incidental), that it
     binds `test-command` on that call, that the value is **exactly** `node scripts/check-skill-lint.test.mjs` (a `|| true` suffix
     would leave the job green while the gate can never go red), that `node-ci.yml` declares that input,
     that the `unit-test` job exists, that BOTH the job and custom-step `if:` are exactly the known-good
     predicates (an added conjunct can make the job unsatisfiable while every check stays green), that
     the custom-test step actually `run:`s the input, that no `continue-on-error:` appears in the
     `unit-test` job block, and that the **caller** `ci:` job carries no `if:`/`continue-on-error:` (the
     most natural way to disable a workflow, and invisible to a callee-only check). The workflow text is
     **normalized before matching** (quote-aware comment stripping + key dequoting, `key :` spacing
     tolerated, and the step's `run:` anchored to its own indentation and EOL): without it, quoted keys
     (`"paths-ignore":`) and `continue-on-error : true` unplug the gate while the guard stays green, and
     trailing comments false-RED healthy files — both classes were reproduced during review. Without it the gate
     can be silently unplugged by removing the binding (the job skips) — and `actionlint`
     cannot catch it. **Caveat:** it reads the BRANCH-LOCAL `node-ci.yml`, while `ci.yml` executes
     `@main`; a main-side change to a stale branch is invisible, so the live per-PR run (Verification
     step 4) is the proof — and that proof **expires** at the next main-side `node-ci.yml` change, which
     is why alternative F's extraction is the durable fix.
   - **`(h)` pin-count assertion** — a presence check (`matched > 0`) was the first attempt; it stayed
     green when coverage collapsed 6 pins → 1, and the follow-up *roster* (name set) also stayed green
     when 3 of subagent's 4 pins were deleted. It now asserts the per-extension pin **count** map.
   All three guards were negative-tested: each verified **red** against a deliberate mutation (pin drift,
   mirror-stamp drift, removed `test-command` binding, removed pins) and the tree restored.

## External Research (Phase 1.5 artifact)

### Axis Research

**Axis 1 — runtime-dependency version pinning + drift detection in CI.** Reframed: agent-infra does not
pin Node itself; the version-sensitive runtime is the pi CLI, globally installed and updated
out-of-band by `pi update`. Canonical practice for this shape is **exact `devDependencies` pin +
committed lockfile + frozen `npm ci`**; global CLI installs are the known anti-pattern because they
bypass the project lockfile and silently upgrade. Toolchain managers (mise/asdf/volta/corepack) pin
*language* toolchains, not an npm-published subject-under-test, so they are not the canonical mechanism
here. Pitfalls confirmed: dev-only/global deps cause green-local/red-CI; registry-mirror lag can resolve
a newer patch than a dev machine unless installs are frozen; global installs get silently upgraded.
**Assessment: validates the existing design — validate, don't redesign.** Residual pitfall: keep the
devDep pins exact (never `^`).
*(Sources: Semaphore, npm official docs, Baeldung, Graphite, plus practitioner write-ups on npm
supply-chain and monorepo pinning pitfalls. 4 queries, 2 per axis, budget met.)*

**Axis 2 — transitive dependency substitution risk on lockfile regeneration.** Standard verification:
`npm ci` on a clean checkout (errors when lockfile and `package.json` desync), generate with
`npm install --package-lock-only` rather than a dirty install, and inspect the graph (`npm ls` /
tree diff) before merging. Documented failure mode is *unreviewed* transitive additions riding in on a
regen or a bad merge-conflict resolution. **Assessment: no new mechanism needed** — verification was
internal and definitive: (a) `@earendil-works/chord` is same-publisher first-party (scope
`@earendil-works`, released 0.85.0/0.85.1 on the pi 0.85.1 timeline), so the typosquat/unknown-publisher
risk model does not apply; (b) an authoritative repo sweep found **zero** references to `chord`,
`pi-client`, or `pi-protocol` in any source file — the substitution is purely transitive; (c) the three
lockfiles resolve cleanly and reproducibly (see "Lockfile verification"); (d) `npm ci` is already the CI
install mode in all three extensions.

### Fix round — code-review cycle 7 (final, at `e1960da`) → guard normalization

The final adversarial pass reproduced nine YAML-valid edits that left the guard GREEN while the gate was
unplugged (quoted keys `"paths-ignore":` / `'paths-ignore':`; `continue-on-error : true` and
`if : false` with space-before-colon; `run: ${{ inputs.test-command }} || true`; a decoy
