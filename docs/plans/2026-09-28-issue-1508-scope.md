## Confirmed Problem Definition

**The failover hop's availability predicate has no term for "this leg cannot authenticate", so a
latched primary advances pre-spawn onto a declared-but-unkeyed leg, and the dispatch dies naming a
provider nobody chose.**

Scope is the two-part unit **RC1 + RC1b**. RC1 alone is inert — see *RC1b* below.

### RC1 — the hop predicate is credential-blind

`unavailableProviders()` (`extensions/shared/provider-failover.ts:980`) → `blockedLegSet()` (`:950`)
is the union of exactly three sets: the env block list, durable auth blocks, and fresh
own-exhaustion records. **No credential term.** `nextLegAfter` (`:1024`) skips only on that set
(`:1055`), so a provider with no key and no models is a *fully available* hop target.

### RC1b — the obvious fix is inert, and this is the finding that decides the seam

The natural repair is to ask the existing credential helper at the hop site. **It would not work.**
`providerApiKeyEnvRef` (`extensions/builtin-tools/index.ts:772`) is built on `loadModelRegistry()`
(`:258`), which reads **only `models.json`** and never merges extension `registerProvider` calls.
Live `models.json` gives `openrouter` = `{modelOverrides: {...}}` — no `apiKey`, no `models` — so the
helper returns `undefined`, which `gateOffTableRequest` explicitly treats as *"pass through
UNCONDITIONALLY"* (`:812-818`). A hop predicate built on it would **not** skip openrouter, and this
exact incident would reproduce.

The correct oracle already exists on the extension context — `ctx.modelRegistry.getApiKeyForProvider`
/ `hasConfiguredAuth` — and the task tool **does** receive `ctx` (`index.ts:4499`). The knowledge
exists; the hop path consults it only for off-table asks (`gateOffTableRequest` `:798`,
`altGateEligible` `:867`), never for hop targets.

## Adversarial Threat Surface

This is not security enforcement, but the change introduces a **fail-open risk** in the dispatch
path, so the surface is declared and bounded:

**In scope — each with the adversarial input and the required behaviour:**

| # | Bypass class | Input | Required behaviour |
|---|---|---|---|
| T1 | A leg with no credential is selected | latched primary, hop target keyless (this incident) | skip it; never spawn it |

## Amendments (post-gate) — resolution of the three P1s

### F-3 closed: Phase 1.5 external research fired

Rung 2 (`web_search model="sonar"`) — rung 1 (`mcp_load seo-intelligence`) is unavailable on this
machine. 8 searches, 6 primary-source fetches, no gated models. Full brief:
`#issuecomment-5873056079`.

The load-bearing finding: **the ecosystem runs two gates, and we have one.** Kubernetes readiness
("controls whether a Pod receives traffic"; Services do **not** fall back to unready Pods) and Envoy
active health checking (a failed host is "excluded from load balancing") are an **eligibility**
precondition on *selection*; observed-failure ejection is the second gate. `unavailableProviders()`
is entirely the second kind. That is the gap, and it is a recognised pattern rather than an invention.

**The counter-case is real and was taken seriously.** The strongest argument is that the defect is
the **missing failure signal**, not the credential-blind predicate — a dead leg that surfaced as a
failure costs one attempt, not a 30-minute outage. Credential-gating is an optimisation layered on a
defect it does not fix, and it adds state that can be wrong in the **other** direction (a stale
verdict removes a *usable* leg — the mirror of the bug). Supporting mechanisms: Envoy/Kubernetes
explicitly disagree about each other's state; a 429 is routinely surfaced as `"Authentication error"`;
keys are hot-reloaded (so absent-at-selection ≠ absent-at-call); and **presence ≠ entitlement** (a key
can be valid for only some models, or OAuth-refreshable).

**This is why the blocking question below mattered more than the gate term itself.**

Also recorded, not settled: **no LLM gateway found documents credential-presence as a *selection*
precondition** — the fix would be ahead of documented practice in that layer while matching the
load-balancer/health-check layer. The alternative that the evidence does **not** rule out: a
**config-time hard failure** (refuse to start when a declared leg has no key) instead of a
selection-time gate. Kept as a live option for Phase 3. **Adoption gate:** no recorded decision is
contradicted — adopt/adapt on the issue, not an owner gate.

### The blocking question, settled: the oracle is a LIVE read and is safe

Settled from the pi source (`@0.85.1`), not assumed — because a **cached** verdict would make the fix
actively harmful. Full trace: `#issuecomment-5873322759`.

`getProviderAuthStatus(id)` (`dist/core/model-runtime.js:411`) resolves in order:
`credentials.hasRuntimeApiKey` (LIVE) → `snapshot.storedProviders` (SNAPSHOT) →
`configuredRequestAuthStatus(config, extensionProviders.get(id))` → `snapshot.auth` (SNAPSHOT).

Step 3 is decisive. `configuredApiKey = extension?.apiKey ?? config?.apiKey` — **the extension
provider is read first**, which is exactly what `loadModelRegistry()` (models.json-only) cannot see,
so **RC1b is confirmed with its mechanism**. For an env-var-declared key it calls
`isConfigValueConfigured` → `resolveEnvConfigValue(name, env) = env?.[name] || process.env[name]`,
evaluated **at call time** — a live read. It returns **`{configured: false}`**, a *truthy object*, so
`if (configured) return configured;` **short-circuits and does not fall through** to the stale
snapshot (`undefined` is the fall-through signal; `false` is a verdict).

**Therefore the openrouter case — declared `$OPENROUTER_API_KEY`, env var absent — is answered live
and cannot be masked by a stale snapshot.** The oracle is trustworthy for this fix.

**Residual (bounded, must be disclosed):** a provider declaring **no** apiKey (OAuth/ambient) returns
`undefined` at step 3 and falls through to the possibly-stale step 4, where a stale
`{configured:false}` could wrongly exclude a usable leg. Both paths return `{configured:false}` with
no `source`, so they are **indistinguishable through this API**. The residual is therefore
**contained by T2, not eliminated** — skipping must fail loudly and name the excluded legs.
