# Issue #207 — main-worktree-guard: TTL'd file-based escape marker for mid-session escalation

Status: IMPLEMENTED — all tasks executed in the issue-207 worktree, 2026-08-13 (see Plan-review history / Task 6 verification)
Branch: feat/207-main-edits-marker
Date: 2026-08-12
Level: project | Complexity: standard | Team: organisation-design-team

**Goal:** Give a guard-blocked-but-functional session (alive, issuing tool
calls, stranded in the shared main checkout) a **sanctioned, bounded,
audited, session-scoped** mid-session escalation: `touch
~/.pi/agent/.allow-main-edits` inside a guard-loaded session opens a
15-minute, re-stamped, audit-logged window for that session only. Upgrades
the only escape reachable today — the undocumented, unbounded, unaudited
`/tmp/recover.sh` + `bash` script-execution backdoor (scope finding F0) —
into a bounded hatch. Fixes the **guard-blocked** class, NOT the
hung-process class (no owner: #203 is CLOSED with a different scope —
process-supervision follow-up, new issue, out of scope).

---

## Confirmed problem

A guard-blocked-but-functional session — alive, issuing tool calls, sitting
in the shared main checkout where the guard blocks destructive git ops
(`git checkout main`, `git pull`, branch recovery) and main-checkout
write/edit — has **no sanctioned, bounded mid-session escalation path**.
The env hatch (`AGENT_ALLOW_MAIN_EDITS=1` / `ELDATO_ALLOW_MAIN_EDITS=1`) is
fixed at session start and cannot be set on a running process. The only
hatch reachable mid-session today is an **undocumented, unbounded,
unaudited script-execution backdoor**: the session writes `/tmp/recover.sh`
(write tool: ALLOW outside project) and runs `bash /tmp/recover.sh`
(`allow-non-git`) to execute arbitrary git ops unblocked. The marker
upgrades that unbounded bypass into a bounded (15-min TTL), audited,
session-scoped one.

**Boundary (explicit):** a HUNG process cannot issue any tool call, so it
can never touch a marker. The hung-process class currently has NO owner —
#203 EXISTS on GitHub but is CLOSED with a DIFFERENT scope (auto-sync
non-main-branch recovery, not process supervision). A process-supervision
follow-up (new issue) is required and is out of scope here. The script
backdoor is **documented in the README, not closed** (closing risks false
positives on legitimate script use; recorded as a possible follow-up).

## Chosen approach

**TTL'd file marker with guard-stamped session scoping, pure logic in
classify-git.mjs, shared audit logging, and both doc deliverables** (scope
Decision 1–7, implemented exactly; no deviation).

- **Marker file:** `~/.pi/agent/.allow-main-edits` — built with
  `join(homedir(), ".pi", "agent", ".allow-main-edits")`, never hardcoded.
  Content: one JSON line `{"session_id","reason","ts"}`.
- **TTL:** mtime-based, `ALLOW_MAIN_EDITS_MARKER_TTL_MS = 15 * 60 * 1000`
  (named, exported, single source of truth), **NON-env-overridable**
  (security parameter — no second weakening knob; testability via
  function params `(stats, nowMs, ttlMs)`). Strict `<` comparison
  (`(nowMs - st.mtimeMs) < ttlMs`); a marker exactly TTL old is expired.
  `touch` refreshes the window. **Re-read per tool_call, never cached**
  (no module-level marker state; proven by the stale-mtime integration
  test — same read call, different results across a touch).
- **Pure logic home — classify-git.mjs** (dependency-injected,
  `isAgentInfraRepo(cwd, env)` pattern; imported by index.ts via jiti AND
  test.mjs): `ALLOW_MAIN_EDITS_MARKER_TTL_MS`, `isAllowMarkerActive(stats,
  nowMs?, ttlMs?)`, `isAllowMarkerPath(path, home)`, `isAllowMarkerCommand(
  command, home)` (touch detection with `~`/`$HOME` expansion incl.
  quoted; printf/echo-redirect deliberately out-of-contract → false),
  `extractMarkerReason(command)` (trailing `# reason` comment),
  `parseMarkerContent(content)` (object | null),
  `isAllowMarkerRealpath(path)` (SOLE symlink defense — block when
  `realpathSync(path) !== resolve(path)`; throw → false), and
  `readAllowMarkerState(path, sessionId, nowMs?, ttlMs?)` (fs read:
  realpath → statSync → isAllowMarkerActive → readFileSync →
  parseMarkerContent → session match; any failure → false → block).
- **Session scoping:** `sessionId = process.env.PI_SESSION_ID ??
  ctx.sessionManager?.getSessionId()` (env first — per-process scoping).
  Active ⟺ mtime fresh AND content parses AND `session_id === current id`.
  Subagents get their OWN id (pi writes it only into bash-tool child envs;
  a subagent touch RE-SCOPES the marker to the subagent — documented:
  **recovery must run in the creating session; delegation does NOT work**).
  Headless null-id sessions (no env, no ctx) cannot escalate (fail-safe
  block).
- **Guard-stamping at creation-observation:** when the per-tool_call
  handler sees an ALLOWED bash command targeting the marker path, it
  writes the stamp `{session_id, reason, ts}` (try/catch fail-silent)
  BEFORE allowing the command; `touch` then refreshes mtime and preserves
  content (no ordering race — touch never rewrites content). **Ordering
  pinned: git classification runs FIRST** — a blocked command never
  stamps, so `touch ... && git checkout main` in ONE call is blocked
  (classification precedes stamping; the git part blocks and the touch
  never runs — documented + tested). Touch must be its own command; the
  recovery git op goes in the FOLLOW-UP call.
- **Audit:** shared/audit-log.ts `appendJsonl` →
  `~/.pi/agent/audit/gate-events.jsonl`, `event: "gate_bypass"`, `reason:
  "main_edits_marker"`, carrying `session_id`, `marker_path`, `ttl_ms`,
  `expires_at`, and the raw marker content (a bare touch still records a
  timestamped creation). No `GateEventName` union change. Stamp write +
  audit wrapped try/catch fail-silent. Plus a one-line `console.log` at
  stamp time.
- **Fail-safe:** absent / unreadable / expired / unparseable / unscoped /
  mismatched / symlinked / import-failure → BLOCK (never silently allow).
  Env hatch unchanged — the marker is an additional OR branch, never a
  replacement.
- **Check placement:** per-tool_call early return at index.ts ~:95
  (`if (isAgentInfraRepo()) ...; if (_isAllowMainEdits() ||
  readAllowMarkerState(...)) return undefined;` — covers bash + write +
  edit, one check point) + session-start hub-warning suppression parity at
  ~:240.

Execution order: T1 → T2 → T3 (red-green alongside T1/T2) → T4 → T5 → T6.
Test runner: `node extensions/main-worktree-guard/test.mjs` (from any
agent-infra checkout — plain node, no deps).

### Task 1: Pure marker logic in classify-git.mjs

**Intent:** All marker decision logic lives in the shared pure module so
test.mjs exercises the SAME rules as index.ts (established
`isAgentInfraRepo(cwd, env)` dependency-injection convention, header
comment: *"Pure JS so both index.ts (via jiti) and test.mjs can import the
SAME rules"*).

**Acceptance:**
- classify-git.mjs exports exactly:
  - `export const ALLOW_MAIN_EDITS_MARKER_TTL_MS = 15 * 60 * 1000;` — named
    constant, single source of truth, **never env-overridable**.
  - `isAllowMarkerActive(stats, nowMs = Date.now(), ttlMs = ALLOW_MAIN_EDITS_MARKER_TTL_MS)`
    → boolean. `!stats` → false (absent, fail-safe); age =
    `nowMs - stats.mtimeMs`; non-finite age → false; return `age < ttlMs`
    (strict `<`; negative age = future mtime → true, documented same-user
    trust bound).
  - `parseMarkerContent(content)` → object | null. `JSON.parse(content
    .trim())`; non-object / parse throw / empty → null. Returns the parsed
    `{session_id?, reason?, ts?}` object (missing fields are the read-side
    match's problem, not the parser's).
  - `isAllowMarkerPath(path, home)` → boolean. `resolve(path) ===
    resolve(join(home, ".pi", "agent", ".allow-main-edits"))` — exact
    match after resolve; traversal / sibling / `/etc/passwd` candidates →
    false; throw → false.
  - `isAllowMarkerCommand(command, home)` → boolean. True ONLY for a
    bare `touch <path>` (optional trailing `# reason` comment) where the
    expanded path is the marker path. Token expansion: strip surrounding
    quotes, expand `~` and `$HOME` (incl. `"$HOME/..."` and `'$HOME/...'`
    quoted variants) BEFORE `resolve()` + exact match via
    `isAllowMarkerPath`. Rejects command chains containing `&&`, `;`,
    `|`, `$(...)`, backticks (one-command-per-touch contract, F10c).
    **`printf`/`echo`/redirect to the marker path → FALSE** (out-of-
    contract: the shell write clobbers the stamp → unscoped → blocked;
    documented fail-safe, not a supported flow — scope Decision 2, test 18).
  - `extractMarkerReason(command)` → string | null. Trailing `# reason`
    comment → trimmed string; absent → null.
  - `isAllowMarkerRealpath(path)` → boolean — the SOLE symlink defense.
    `realpathSync(path) !== resolve(path)` → false (reject ANY symlink
    indirection; `~/.pi/agent` is not a symlink in this fleet); throw
    (broken link / ENOENT) → false. No `isSymbolicLink()` branch anywhere
    (statSync follows symlinks — never fires in production, F6/round-2 F3).
  - `readAllowMarkerState(path, sessionId, nowMs = Date.now(), ttlMs =
    ALLOW_MAIN_EDITS_MARKER_TTL_MS)` → boolean (active for THIS session):
    `if (!isAllowMarkerRealpath(path)) return false;` → `statSync(path)`
    (throw → false) → `isAllowMarkerActive(stats, nowMs, ttlMs)` → false
    → stop → `readFileSync(path, "utf-8")` (throw → false) →
    `parseMarkerContent` → null → false → `typeof session_id !==
    "string"` OR `sessionId` falsy OR `session_id !== sessionId` → false;
    else true. Whole body in try/catch → false.
- Existing exports untouched; the header comment gains the marker exports
  note; `node:fs` import grows `statSync, readFileSync, realpathSync`.
- Existing 65-assertion suite still green after the change (regression).

## Runtime prerequisites & risks

- **Node runtime:** current fleet runtime suffices (`fs.Stats.mtimeMs`,
  `JSON.parse`, `realpathSync` — all stdlib, already in use).
- **`PI_SESSION_ID` semantics (verified in scope round-2 F1/F2):** env
  first; pi writes it into bash-tool child envs (confirmed present in
  this session's env) — the extension host resolves per-process ids;
  subagents get their own id; headless → null → fail-safe block. Risk:
  `ctx.sessionManager` availability in the `tool_call` handler is
  unproven (only `registerTool` callbacks proven) — mitigated by the
  env-first design; if both resolve null the marker can never be active
  for that session (fail-safe, no false allows).
- **Symlink posture:** `~/.pi/agent` is not a symlink in this fleet
  (verified) — on a machine where it is, markers block (fail-safe). The
  realpath-inequality check is the SOLE symlink defense (no
  `isSymbolicLink` branch — statSync follows symlinks).
- **No caching:** module-level marker state is forbidden — the stale-
  mtime test (case 23) makes any cache provably fail.
- **Audit failure:** `appendJsonl` never throws; the marker content
  carries session_id + reason so creation is self-describing even if the
  audit write fails (F10d dilution: a reason-less activation is visible
  but its purpose field is null).
- **Known accepted bounds (documented, not fixed):** same-user trust
  (a rogue same-user process can already kill/steal the session; mtime
  forgeable via `touch -d`); the script-execution backdoor stays OPEN
  (documented; closing = possible follow-up); hung processes have NO
  owner (process-supervision follow-up, new issue — out of scope);
  machine-global file within TTL for non-escalating sessions is
  contained by session-scoping (a parallel session's touch re-scopes to
  the toucher and blocks the first session again).
- **One command per touch:** combined `touch && git ...` one-liners do
  NOT work (classification precedes stamping) — documented in README +
  skill + tested (case 22).
