## 1. Problem statement

Three code-review P2 residuals / deferred gaps from #472 (verification-gate proportionality), fail-closed-direction issues accepted at merge but worth closing:

1. **T1 (2a-1) — rename-source hole (fail-open).** The content-shape VGATE exemption reads the changed-file set produced by **name-only** diffs. A rename/copy row collapses to its NEW path only (`git mv src/app.ts docs/code.md` → `git diff --cached --name-only` lists `docs/code.md`), so deliberate code→docs content moves ride the docs exemption with no verification — same class as copying code into a fresh `.md` (the copying class is accepted as inherent to the extension-keyed design; the rename class is detectable and this issue closes it). Empirically confirmed: renames appear as `R<score>\t<old>\t<new>` under default rename detection and name-only emits only the new path. With `diff.renames=false` the D+A split already surfaces the old path → gated today (no hole, no regression). **Copy rows** fire only when the copy's source is itself modified/deleted in the same diff (git `-C` semantics — verified: a copy of an UNMODIFIED source emits a plain `A` row even under `diff.renames=copies` + explicit `-C`); where a C row fires, the old code path → gate ON (correctly fail-closed), and a copy of an untouched source under copies config remains the accepted copying residual (plain A row — stated precisely in the rewritten trust-boundary comment; no blanket C-gating claim).
2. **T2 (2a-3) — findGitCommit `-c`-value mis-parse.** The regex at L849 (`\bgit(?:\s+-[^\s]+(?:\s+(?!commit\b)(?:'[^']*'|"[^"]*"|\S+))?)*\s+commit\b`) consumes a global option's VALUE only when it does not start with a commit-prefixed word; the negative lookahead `(?!commit\b)` then fails at the value (`commit.gpgsign=false` has a word boundary after `commit`), so the verb group `\s+commit\b` binds the **value's** `commit`. `isBareCommitShape("git -c commit.gpgsign=false commit -m x")` empirically returns `false` (must be `true`) — fail-closed friction. Related false-positive class (fail-closed, #487-recorded): `git -c commit.gpgsign=false pull --rebase … && git push` chains are mis-read as commit-bearing → has_commit → staged scope.
3. **Interception gap (fail-open; docs/comments defer to #490).** `isGitOp`/`isGitCommit` use `GIT_COMMIT_PATTERN = /(^|\s)git\s+(commit|push)(?=\s|$)/`, which never fires for **cwd-neutral** global-option spellings (`git -c x=y commit`, `git --no-pager commit`). A pure `git -c commit.gpgsign=false commit -am x` over dirty code today ships **unverified** (fail-open). 01-preflight.md L345-346 says "NOT yet intercepted … (open #490)"; the #489 sweep unit pin comment (index.test.ts L1747) and commitSweepClass's doc comment (index.ts L978) both track this gap to #490.

**Boundary decisions (scope converge + review cycles 1-4; §1 additions from cycle-4/5 review):**
- **Interception widening covers cwd-neutral git globals** — `-c <name>=<value>` (space-separated ONLY; git rejects attached `-cNAME=VALUE`/`-C/path` — "unknown option", verified) and boolean globals (`--no-pager`, `-p`, `-P`, `--paginate`, `--bare`, `--no-replace-objects`, …). **Repo-redirecting globals (`-C <path>`, `--git-dir`, `--work-tree`) stay UN-INTERCEPTED** (`foreign`): the hook's verification is scoped to the session checkout; a `-C` commit targets a DIFFERENT checkout the session cannot scope (the code-review fixer-loop ceremony `git -C "$WORKTREE_PATH" commit/push`, skills/code-review/references/fixer-loop.md L122/L130, relies on this today — no ceremony change needed). The classifiers still consume ALL global kinds so containment inside gated commands is unchanged.
- **Env-form redirects** (`GIT_DIR=/x git commit …`, `GIT_WORK_TREE=/x git …`) REMAIN intercepted exactly as today (the inline assignment never reaches the hook's execSync env → session-cwd diff → accepted pre-existing mis-scope status quo; parity-pinned so the boundary line is precise).
- The widening's new-fire surface is slightly larger than the cwd-neutral-global sentence: exact-verb + quote/metachar normalization also newly fires verb-SIDE abutments `sh -c 'git commit'` (verb abutting a closing quote — today `(?=\s|$)` fails), `git 'commit' …`, `git commit&&…`/`git commit;…`, AND git-SIDE abutments (`cd /repo&&git commit`, `(git commit …)`, inline `#git commit` prose — today's `(^|\s)git` anchor requires whitespace before `git`; a quote/metachar character right before `git` fails the same anchor, which is why BOTH `sh -c 'git commit'` AND `sh -c 'git commit -am x'` are red today, the `\bgit\b` candidate scan does not) — all correct-direction closes of silent misses, pinned by representative members (git-side: `cd /repo&&git commit`, `(git commit …)`; verb-side: `git commit&&…`).
- **T1 diff producers switch to `--name-status -z`** (NUL-separated porcelain): git emits path columns RAW (no C-quoting) in `-z` mode — `A\0<path>\0`, `R100\0<old>\0<new>\0` (byte-exact format verified at implementation; parser handles 2-NUL single-path and 3-NUL R/C segments). This eliminates the whole hand-rolled C-quote decoder + ambiguity class at the root: control chars, quotes, tabs and non-ASCII names parse raw and hash correctly. A defensive `clean` flag remains (unreachable from real git output — see §3.3) with pure-decision unit pins, because the allow-site layer must be fail-closed against future format drift.

## 3. Solution

### 3.1 Shared verb-invocation scanner (T2 core)

New module-private core replaces findGitCommit's regex AND drives the interception predicates:

```ts
type GitGlobalKind = "session-value" | "session-bool" | "redirect";
function findGitVerbInvocation(
  text: string,
  verbs: ReadonlySet<string>, // "commit" (classifiers) | "commit","push" (interception/push classifiers)
): { index: number; end: number; verb: string; foreign: boolean } | null
```

- Iterates candidate `git` words (`\bgit\b`, **quote-unaware** — containment over wrapper/prose text must stay symmetric with today's regex, per the #487 coupling note); the word must be followed by whitespace or a bash token boundary. **Tokenizer state starts FRESH at each candidate** (a quote opened before the candidate does not leak into its value tokens — otherwise `git -c "user.name=A B" …` inside prose would mis-terminate; pinned by the `sh -c 'git commit'` + quoted-value interception guards).
- Tokenization: whitespace AND unquoted bash metachars `; & | ( ) < >` terminate tokens (mirrors splitCommandSegments — closes the `git commit&&x` / `git commit;…` silent-miss family); backslash escapes the next char OUTSIDE quotes (`my\ dir` = one value token); **backslash-newline = dropped line continuation** (bash semantics); quoted regions stay one token (`-c "user.name=A B"`); a token that is the verb plus trailing quote chars (`'commit'`, `commit'` at string end) normalizes to the verb.
- **Global-option consumption by KIND:**
  - `session-value` (cwd-neutral): `-c` EXACT token (git rejects attached `-cNAME=VALUE` — "unknown option", verified; an attached-looking `-c…` token falls to the unknown-dash heuristic below) consumes ONE following token atomically — even `commit.gpgsign=false`, `commit`, `precommit`, or a quoted `"user.name=A B"`.
  - `session-bool` (cwd-neutral, consume nothing): `--no-pager -p -P --paginate --bare --no-replace-objects --literal-pathspecs --glob-pathspecs --noglob-pathspecs --icase-pathspecs --no-optional-locks --no-advice --no-index --version --help`. Long `--x=y` attached forms carry their own value (consume nothing).
  - `redirect` (mark invocation **foreign**): `-C` exact (consume the following value token; attached `-C…` tokens are rejected by git — tolerated), and the redirect longs `--git-dir --work-tree --namespace --super-prefix`: the SPACE form consumes the following token, while an attached-equals token (`--git-dir=/x`, `--work-tree=/x`, … — legal git, verified) carries its own value and consumes NOTHING (mirror of the session-bool `--x=y` carve-out; without it the exact-verb rule would fail after eating the verb and containment would weaken). Foreign invocations are recognized by the CLASSIFIERS (containment unchanged) but never fire the INTERCEPTION predicates (§1 boundary).
  - **Unknown dash tokens** (future globals): if the next token IS the verb → treat as boolean (verb wins); otherwise consume ONE following **non-dash** token (a following dash token is never a value — otherwise `git --no-color -c x=y commit` would swallow the `-c` as `--no-color`'s value and lose the verb; the legacy regex backtracked here). Preserves the legacy tolerance for out-of-table value-taking globals (`--shallow-file /x commit`).
- **Exact-verb rule:** after git + globals, the next token must BE the verb — normalized exactly `commit` / `push`. `commit.gpgsign=false`, `commit-graph`, `commit.txt`, and any VALUE can never bind as the verb. A non-dash, non-verb token ends the candidate (`git status commit.txt`, `git config --global commit.gpgsign false`, `git -c commit.gpgsign=false pull --rebase` → NOT git-op invocations).
- Returns the FIRST parseable invocation. `index` 0 = head-anchored (bare/sweep classification, interception at command head after prefixes); `index > 0` = wrapper/prose (containment only).

### 3.2 findGitCommit + interception + push-recognizer rewiring

- `findGitCommit(stripped)` = `findGitVerbInvocation(stripped, {"commit"})` mapped to `{index, end}` — identical return contract; all four consumers (isDeletionPush, isBareCommitShape, commitSweepClass, parsePushRefSpecs P0 guard) unchanged in structure; the `-c`-value mis-bind disappears everywhere (incl. the #487-recorded `-c commit.gpgsign=false pull --rebase … && git push` chain → no longer commit-bearing → the push classifies on its own range; pins).
- `isGitOp(command)` = `GH_PR_PATTERN` OR `findGitVerbInvocation(command, {"commit","push"})` with **foreign=false only**. `isGitCommit(command)` = same with `{"commit"}`, foreign=false. `GIT_COMMIT_PATTERN`/`GIT_COMMIT_ONLY_PATTERN` regex consts deleted (the scanner subsumes them on plain adjacency and closes the metachar/quote-abutting/backslash-continuation misses). Non-commit verbs and foreign invocations never fire (negatives + boundary pins). Env-form redirects (`GIT_DIR=/x git commit`) stay intercepted (status-quo pin).
- **Push recognizers adopt the verb-scan** (review cycle 1 P1): `isPureDeletionPushSegment` and `parsePushRefSpecs` detect a head-anchored push via `findGitVerbInvocation(stripped, {"push"})` (index 0) and parse the POST-VERB text (`stripped.slice(end)`) with their existing token logic; `isDeletionPush`'s wrapper-push arm uses the verb-scan presence at index>0. Result: `git -c commit.gpgsign=false push origin --delete feat/x` classifies pure-delete (skip, same as the bare form); `git -c x=y push origin main` classifies range-eligible content push; wrapper `sh -c 'git -c x=y push …'` stays unprovable. ALL existing isDeletionPush/parsePushRefSpecs pins stay green (plain forms classify identically through the verb-scan path).

### 3.3 T1 rename-source plumbing (`--name-status -z` + pure gate decision)

- New exported pure parser over NUL-separated porcelain (`-z`):

```ts
interface DiffScope { files: string[]; renameOldPaths: string[]; clean: boolean }
export function parseDiffNameStatus(out: string): DiffScope
```

- Row grammar (`-z`, byte-exact verified at implementation): the output is a sequence of **NUL-terminated tokens with NO record separator** — the trailing NUL is the TERMINATOR of the last token, not an anomaly (a split-based reader drops the single trailing empty element); interior consecutive NULs (an empty token between records — impossible from real git, POSIX filenames cannot contain NUL) or a final token lacking its terminating NUL are the anomalies. Zero-byte output = clean with no rows (a COMMON state feeding the empty-allow route). A single-path row = `A|M|D|T|U|X|B\0<path>\0`; a rename/copy row = `R<score>|C<score>\0<old>\0<new>\0` (3 NUL fields). `files` = new-path projection (== today's name-only set on every row type — parity pinned); `renameOldPaths` = R/C old paths. **No quoting/decoding anywhere** (paths raw). `clean=false` only on a NUL-stream anomaly — unreachable from real git output (defense against format drift; honest prose, no fake-realizable fixture). Pins: `parseDiffNameStatus("")` → clean/no rows; a valid trailing-NUL multi-row string → clean with the full file set.
- Scope producers (module-private; exec error semantics unchanged — catch → `{files:[], renameOldPaths:[], clean:true}` preserving today's silent-empty behavior at each call site): `runStagedScope(cwd)` = `git diff --cached --name-status -z`; `runWorktreeScope(cwd)` = `git diff HEAD --name-status -z` (unborn-HEAD → staged scope; other failures → staged fallback, logged, as today); `runBranchScope(cwd)` = `git diff origin/main...HEAD --name-status -z`. `scopeFiles` L78 + unborn fallbacks consume `.files`.
- Push range: `buildPushRangeDiffCommand(tier, base, src, nameStatusZ = false)` — optional 4th arg; default keeps the three exact-argv pins. `resolvePushRangeScope(command, cwd): DiffScope | null` runs the `-z` form per refspec (unions files + renameOldPaths; `clean` = AND over refspecs; **emits the `push_range_empty` audit inside — it is the hook-called producer**; any existing null condition → null). The old exported `resolvePushRangeFiles` name is DROPPED (repo-wide grep: zero consumers after the hook rewires; e2e scenario 54 drives the hook end-to-end and asserts the audit that lives inside the Scope producer) — `resolvePushRangeScope` is exported for the e2e surface, `parseDiffNameStatus`/`applyScopeGate` are the unit-tested pure seams. Single-audit invariant: exactly one `push_range_empty` emission per empty resolution, in the producer.
- **Pure gate decision** (mirrors the evaluateMergeScope/resolvePushTier I/O-split pattern — makes the defense layer unit-testable without producer injection):

```ts
export function applyScopeGate(
  changedFiles: string[], renameOldPaths: string[], clean: boolean,
  bare: boolean, isExempt: (p: string) => boolean,
): { kind: "empty-allow" } | { kind: "parse-block"; block: { block: true; reason: string }; event: "gate_block_parse_failure" } | { kind: "exempt-allow" } | { kind: "verify" }
```

  `empty-allow` iff `files.length===0 && clean`; `parse-block` iff `!clean` (unconditional — BEFORE empty-allow/exemption/verify/#7591 auto-bypass); `exempt-allow` iff `clean && files.every(exempt) && renameOldPaths.every(exempt) && bare`; else `verify`. Unit pins: `{[],false}` → parse-block on attempt 1 AND 3 (no vacuous auto-bypass); `{exempt-files,false}` → parse-block (never exempt-allow); `{verified-files,false}` → parse-block (mixed valid+malformed never verifies past malformed content). The mixed sweep-union combines the staged and worktree scopes as renameOldPaths = union, clean = clean_staged && clean_worktree, files = the existing dedup union (a staged `git mv` also surfaces as an R row in the WT diff, so the union adds no rename rows the WT scope misses — defensive invariant, not a live path).
- **Hook wiring:** `applyScopeGate(files, renameOldPaths, clean, bare, isExempt)` is a PURE exported function returning one of `{kind:"empty-allow"}` | `{kind:"parse-block", block:{block:true, reason}, event:"gate_block_parse_failure"}` | `{kind:"exempt-allow"}` | `{kind:"verify"}`. The hook calls it as the FIRST post-resolution step and routes: `empty-allow` → `return undefined` (replaces L1962); `parse-block` → emit the returned audit event via `appendJsonl` then `return block` (NO `lastBlockedFiles` write, NO #7591/blockAttempts counter → never auto-bypasses, only ELDATO_SKIP_VGATE escapes; the block return itself does not audit — the event is explicit); `exempt-allow` → existing exemption branch (logGateSkip `content_shape_exempt` + pendingRehash arm unchanged); `verify` → existing verify loop. Because the ONLY scope-early-returns flow through this single routing site (structurally no empty-allow-before-parse-block misordering is possible) and `applyScopeGate` is pure, the parse-block shape/event/ordering invariants are unit-pinnable without a producer seam or audit side effects (the pure function never writes; the hook's emit is 3 lines). Trust-boundary comment (L1995-1999) rewritten: rename sources plumbed (any non-exempt R/C old path forces the gate ON); the copying-code-into-fresh-`.md` residual remains accepted, with the precise C-row trigger (fires only when the copy source is also modified/deleted in the same diff; a copy of an untouched source emits a plain A row and stays the accepted residual even under `diff.renames=copies`); AND the tree-observability limit: R rows fire only when the rename source exists in a compared tree (base/HEAD/index) — code content whose path is docs-shaped at EVERY observable tree (in-session add→mv, in-range add→mv) is structurally indistinguishable from a docs create and remains the accepted residual (no total-closure claim).

## 4. Rejected alternatives

1. **Dedicated rename probe** (second name-status diff only when the exemption is eligible): duplicates push-range ref resolution; two observations can diverge — per-producer name-status chosen.
2. **Force `--find-renames` on the status diffs**: diverges from name-only behavior under `diff.renames=false` (would re-pair D+A into R rows and hide the old path under that config) — status diffs must mirror name-only rename detection config-consistently.
3. **Non-`-z` porcelain + hand-rolled C-quote decoder + row-grammar `clean` machine** (cycle-1 design): git C-quotes `"`/`\`/control chars in every column under any quotepath; the decoder + malformed-row grammar existed only to patch that quoting. `-z` removes quoting at the root — rejected in favor of `-z` (cycle-2 GOOD>EASY adoption); `clean` retained as defense-only + pure-decision pins.
4. **Regex patch to findGitCommit**: a regex cannot express value-taking vs boolean global options (the lookahead IS the bug); removing it breaks `git --no-pager commit`. Scanner is the minimal correct engine.
5. **Head-anchor findGitCommit only**: breaks the #487 P0-guard wrapper containment — explicitly forbidden by the #487 plan coupling note. The scanner keeps substring containment and applies the head-anchored grammar per candidate.
6. **Mirror the scanner in widened regex patterns** for isGitOp: the regex mirror provably fails open on `-c commit.gpgsign=false commit` (value can't be consumed atomically) — scope verifier P1. Interception and classifiers share ONE scanner.
7. **Full widening incl. `-C`/`--git-dir`**: newly intercepts repo-redirecting spellings the hook cannot scope (wrong-checkout diff → mis-scoped blocks) and breaks the code-review fixer-loop `-C` ceremony — review-cycle-1 P1. Excluded via the `foreign` flag; pre-#490 behavior for redirect forms preserved and pinned.
8. **`clean=false` = refuse exemption only**: a scope with malformed rows and every parseable file verified still allows — must block unconditionally BEFORE the empty-allow/exemption/verify/#7591 chain (review-cycle-1 P1 + cycle-2 ordering P1) — adopted into §3.3.
9. **Stub-based hook testing of the `clean` layer** via an exported producer seam: no clean seam exists and the producers are module-private; the pure `applyScopeGate` decision function (pattern precedent: evaluateMergeScope/resolvePushTier) returns the block shape + audit event so the parse-block invariants are unit-pinnable without side effects (cycle-2 P1 + cycle-3 P2 adoption).
