**Adversarial challenges:**
- A: "Main's hard cap already bounds the wait — why not just lower
  TASK_HARD_CAP_MS?" Lowering the flat cap reintroduces #489 (kills
  legitimately-long tool calls); the marker-gap clause is the discriminating
  detector (only fires when markers freeze while tools are in flight). The
  hard cap stays as the last-resort bound.

  children." It handles the COMPLETED class; the wedged-alive-frozen-markers
  class (and the exit-before-close pipe-holder class) still resolve only at
  the 2h cap. The cut clause + exit-settle target exactly those classes,
  aligned with sessionEnded so completed sessions still resolve clean.

#250 success-path regression guard explicit in the targets.

## Stage 3 — Scope (design from de088e7, verified)

**Confirmed problem:** wedged-alive (markers frozen, toolsInFlight>0) and
pipe-holder (exit before close) classes resolve only at the 2h hard cap —
#208's "<60s partial results on cut" target is unmet on main.

**Approach (recover de088e7's builtin implementation, rebase onto main):**
1. `heartbeatKillDecision` gains the marker-gap 'cut' clause:
   `toolsInFlight > 0 && markerAge > cutGapMs` (cutGapMs = 1.25×interval,
   floor 15s, env TASK_HEARTBEAT_CUT_GAP_MS), gated `!sessionEnded`; reason
   "cut" added to HeartbeatKillReason.
2. exit-settle grace-race (2s, DEFAULT_EXIT_SETTLE_GRACE_MS): `proc.on('exit')`
   defers settle; per-dispatch `settled` flag (already on main) runs settle
   exactly once. On BOTH close (within grace or late) and exit-settle, run ONE
   sessionEnded-aware finalize (verifier P1): if `state.sessionEnded` → main's
   `composeTaskResult` (success, killedAfterCompletion/exitCode in details,
   completion watchdog disarmed — #250 path untouched); else → de088e7's
   `classifyTaskExit` (signal-death null → cut; code 0 + frozen
   toolsInFlight>0 → cut; code 0 + tools=0 → success; non-zero → failed) with
   `resolveUndefined = !hasOutput` on the cut branch (zero-partial cuts stay
   retryable). AC1/AC11 (close-path cut) and the #250 success-path guard both
   covered by this single branch.
3. Detector-dead backstop (TASK_BACKSTOP_MS = tool-stall + 30min): fires only
   when stateFresh === false (healthy ticking agents re-arm). PRECEDENCE
   (verifier P2): main's hard cap (TASK_HARD_CAP_MS default 2h, NOT
   stateFresh-gated) fires first on defaults — state explicitly that the hard
   cap is the detector-dead last resort on default config and the backstop
   engages when env-overridden below it; AND give the hard-cap composition
   `resolveUndefined = !hasOutput` (match the cut/backstop retryability
   contract) so a zero-output detector-dead wedge is retryable.
4. Detached spawn (TASK_DETACHED=0 opt-out) + settle-path sweep hook using
   extensions/shared/process-sweep.ts (already on main via #268).
5. `resolveUndefined = !hasOutput` on the cut path (zero-partial cuts stay
   retryable).

**Wiring check:** builtin-tools/index.ts + builtin-tools.test.ts +
cut-resume.integration.test.ts (restore from de088e7); no other surfaces.
**Complexity:** standard (builtin core).
