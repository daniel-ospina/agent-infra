# Phase 2: Problem Reframing

Apply research-protocol problem reframing to the domain. Challenge assumptions before researching.

## Steps

### 2.1 Five Whys
Ask "why understand this domain?" up to 5 times. Document the chain:
```
1. Why? →
2. Why? →
3. Why? →
4. Why? →
5. Why? →
```

### 2.2 How Might We
Generate ≥2 alternative framings:
- "How might we understand [domain] without [assumed approach]?"
- "How might we structure [domain] knowledge so [outcome]?"

### 2.3 Assumption Mapping
List every assumption about this domain. Tag each:
- `[validated]` — confirmed by existing knowledge
- `[unverified]` — assumed but unproven

### 2.4 Domain Distinctiveness
What makes this domain distinct from adjacent domains? What are its boundary conditions? What does it exclude?

### 2.5 Problem Statement
Synthesize into a reframed problem statement:
> "[Agent] trying to [understand this domain] but [barrier] which results in [negative outcome]."

### 2.6 Write Artifact
Write to `research/02-reframed-problem.md`:
```markdown
# Reframed Problem: <domain>

## Five Whys
1. ...
2. ...

## How Might We
- HMW 1: ...
- HMW 2: ...

## Assumption Map
- [validated] ...
- [unverified] ...

## Domain Distinctiveness
...

## Problem Statement
> [Agent] trying to [understand domain] but [barrier] which results in [negative outcome].
```

Proceed to Phase 3.
