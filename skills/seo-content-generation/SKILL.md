# SEO Content Generation

> **Source:** Canonical copy at `skills/seo-content-generation/SKILL.md`. Consumers link this dir into
> their `operations/skills/` farm — edit here only.

The standard process for producing one SEO article for the Tortoise blog. It exists because the
pipeline is **not** "write an article, then publish it": the article is *generated by the owner from a
reviewed brief*, and the agent's job is to build the brief to a high enough standard that the owner's
generation pass is worth doing, then to land the result in the CMS correctly.

**The deliverable is the CMS row, not a markdown file in a repo.** A merged `.md` is not a published
article — see the ⛔ below.

**Use this skill when:** asked to write, plan, brief, or publish a Tortoise blog article; add a
comparison page; extend a pillar; or produce any SEO content destined for the blog CMS.

**Article types covered:** comparison (`X vs Y`, `best X tools`), pillar/explainer (category
definition), and how-to. Format norms differ per type — the type is chosen in step 3.

**Repos this spans.** Paths below are absolute only inside the repo that owns them:

| Path | Repo |
|---|---|
| `growth/seo/**` — examples, article workspaces, keyword data | **`premise-labs`** |
| `product/competition/**` — the competitor registry | **`premise-labs`** |
| `website/functions/blog/**` — the CMS API and its SEO modules | **`daniel-ospina/tortoise`** |

Run every `growth/seo/…` command (including the step-4 `open -R`) from the **`premise-labs` main
checkout** — *not* a linked worktree. `growth/seo/**` exists only in the main checkout, so a command

**Steps 5 and 7 are the owner's, not the agent's.** Do not attempt to generate the article text, and
do not publish. Step 5 is deliberate: the owner's own generation + editing pass is what makes the
voice right, and an agent-written draft short-circuits it.

### The human stops

**Three steps stop for a human** — two approval gates (1 and 2) and the owner's generation pass
(step 5). All are **hard stops**. Present, then wait — do not "proceed and let them correct it".

- **Gate 1 (after step 3).** The research doc **and** the brief, **in-line in the conversation** —
  not as file paths. The owner reviews facts and framing before any generation happens. This is the
  cheap place to catch a wrong claim; catching it later means redoing the brief *and* the draft.
- **Gate 2 (after step 6).** The owner reviews the CMS preview. The agent never publishes — and this
  is a **prose control, not a technical one**: the posts API accepts `status: published` with the
  agent key, so nothing but this instruction stops it.

> ⚠️ **The enforcer is a backstop, not the gate — and it can fail open three ways.** The three stops
> are declared `gate: human_approval`; when one is reached, every tool except
> `read`/`web_search`/`web_fetch`/`loop_enforcer` is blocked
> (`extensions/sequence-enforcer/index.ts:1421-1423`). But:
>
> 1. **It is usually never reached.** The index only advances past `auto` steps when a foreign
>    `SKILL.md` is opened (`:1806-1824`), so on a normal run — where you open no other skill — no gate
>    is ever announced and no enforcement fires.
> 2. **A reached gate is a one-turn pause, not an approval.** `agent_end` advances past it with no
>    approval signal (`:1778`).
> 3. **A typo disables it silently.** An unrecognised `gate:` value falls through to "standard work
>    phase" and permits `write`/`edit`/`bash` (`:1432-1433`) — and `frontmatter-validate.mjs` does not
>    check the `gate` enum, so a misspelling passes lint while removing every stop.
>
> **These gates are therefore PROSE controls, not technical enforcement.** Never read "no gate fired"
> as "the owner approved" — the real gate is the explicit, spoken approval you wait for.

## Non-negotiables every article inherits

These come from `growth/seo/README.md` §2 and hold for every article, in every workflow file:

1. **Key takeaways** block at the top — 5–7 bullets, each a defensible claim.
2. **Every number carries a primary source and a date.** No number without one.
3. **At least one real HTML `<table>`** for any comparison **or taxonomy** — never a bulleted list
   pretending to be a table.
4. **Fair-but-favourable.** For each competitor, name the job it is genuinely good for, and state our
   weaknesses where they exist. A table that only flatters us is the one readers discount.
5. **Video embed** (one of V1–V3) plus a link to its transcript page.
6. **Internal links:** the pillar page, 2 sibling articles, 1 docs page.
7. **A "test it yourself" section** with a runnable step.
8. **Claim discipline.** Any sentence of the form *"nobody / only / never / the only / sole"* must
   name a checked source or be cut.

### Three failure modes that produce real defects

- **Never convert a searched absence into a positive assertion.** "We found no published statement by
  X" is supportable. "X publishes no…" is not — a failed search is not evidence of absence.
- **A first-person shipped/not-shipped claim about Tortoise is P0 until verified against
  `daniel-ospina/tortoise` at a named commit.** Grant docs, research briefs and this skill are
  **not admissible evidence**, and a reworded claim is not a fixed one — re-derive the fact from the
  source, or remove the claim.
- **A claim about the process has no artifact to check, so it re-stales on every edit.** "we narrowed
  this later", "the word count is now", "this is the final version" — delete it. Do not reword it, and
  do not narrate the journey instead of the change: describe the change and the evidence for it, never
  the sequence of edits that produced it.

**Marketing is about "best for", not uniqueness.** The spine of an article is a **positive, argued
positioning claim** — never a negative universal about the field. A negative-universal spine is the
single largest source of non-converging review: it sends the writer hunting for a claim strong enough
to survive an adversary, instead of arguing the one we can support.

## What fails if you skip this process

| Skipped | Failure it caused |
|---|---|
| Step 1 (examples) | Articles written to taste, not to the measured format of what actually ranks. |
| Step 2 (research) | Unverifiable numbers printed as fact — two were caught only by a reviewer checking the registry they were attributed to. |
| Gate 1 | The owner's generation pass runs on wrong facts; the brief and the draft both have to be redone. |
| Step 3's keyword targets | The article ranks for nothing it was meant to; the keyword data exists and was not used. |
| Step 6's wiring check | Our keywords are never injected into the meta fields — the post publishes with generic SEO text. |
| Any merged-`.md` "publish" | Work is reported as delivered that no reader can reach. |
