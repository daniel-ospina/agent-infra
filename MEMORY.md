- [tmux/has-session]: a "did my new-session actually start something?" check needs TWO waits because the single check lies in BOTH directions — a DEAD pane's session LINGERS (tmux tears it down a beat later, not synchronously: `new-session -d -s S "exec bash -c 'exit 7'"` returns 0 and `has-session -t =S` is TRUE, FALSE ~300 ms later), and a COLD server is not yet VISIBLE (`new-session -d` returns 0 while `has-session` can MISS for a moment, so a first-miss read as death is a FALSE FAILURE — measured as an exit 69 at a 200 ms first check while the session appeared right after) → wait for APPEARANCE (bounded poll, miss ≠ death), THEN require it to STILL be there after a settle window (a); a suite that only does the second wait is flaky on a cold socket, one that only does the first proves nothing.
