# MEMORY.md — raw coding gotchas

> Memory contracts: append on task complete when a code gotcha surfaced. Cap 150 lines. Format: `[category]: [what broke] → [root cause] → [the fix]`

- [watchdog]: task sub-agent first-message-stall cut LIVE tool-first sub-agents → pi emits `turn_start` PER LLM CALL (pi-agent-core agent-loop.js), child+parent reset per-turn flags on each turn_start, AND tool_end/turn_end/turn_start never reset the parent's parsed streamAgeMs → a quiet verdict turn (or frozen-age turn transition) hit the 300s wall-clock bound despite fresh heartbeats → fix: parent-side `everSawRealActivity` latch (tool_start/tool_end/tick saw_msg/saw_tool/tools>0; NEVER bare ready/turn_start) gating the clause + streamAgeMs/toolAgeMaxMs resets at tool_end/turn_end/turn_start (extensions/builtin-tools/index.ts, #279).
- [tests]: builtin-tools tick parser regex `([a-z_]+)=(\d+)` does NOT match underscore-separated numbers → `stream_age_ms=600_000` parses as 600 → use plain integers in marker fixtures (E279 series).
- [tests]: `subagent-integration.test.ts` uses process.cwd()-relative paths (`join(process.cwd(), "extensions", ...)`) → run from the REPO ROOT (`npx tsx extensions/builtin-tools/subagent-integration.test.ts`); running from inside `extensions/builtin-tools/` yields a doubled-path ENOENT.
- [watchdog]: a child's background-timer tick proves process liveness, NOT work progress — a hung provider request keeps ticking; only work-loop signals (message/tool events) prove progress. Distinguish the three questions (liveness/activity/downstream) in separate watchdog clauses (K8s three-probe lesson; dora-rs "busy-but-silent" incident).
- [subagents]: `resolveUndefined = !hasOutput` per kill — a cut with only non-marker startup stderr resolves a DEFINED partial (not retryable); a zero-output cut is retryable-undefined (feeds the retry wrapper + circuit breaker, which trips at 3 undefined strikes session-wide).
- [research]: Tortoise memory offline without TORTOISE_API_KEY — `tortoise-memory.mjs` prints `tortoise_unavailable` and exits 0; research skills degrade gracefully (skip epistemic checkpoint).
- [gh]: GraphQL rate limit resets independently of REST — when `gh issue comment`/`gh pr merge` fails with "GraphQL: API rate limit exceeded", fall back to REST (`api.github.com/repos/.../issues/N/comments` POST, PATCH issues/N) which shares the core REST quota.
- [git]: `git stash pop` can silently drop a stash whose diff doesn't re-apply to a moved base — recover from the dangling stash commit (`git fsck --no-reflogs | grep dangling`, `git show <hash>:<path>`).
- [commit]: the review-enforcer merge gate needs `scripts/record-review.sh <PR> <head_sha> clean <owner/repo>` BEFORE `gh pr merge` — run code-review to convergence, record the verdict, then merge (never `--delete-branch`; delete the branch separately).
- [git]: main-worktree-guard mis-parses compound bash commands — unexpanded `$VAR` in `git checkout -b "$VAR"` records a literal baseline, and pipes/redirects (`2>&1 | tail`) get parsed as push refspecs → run git ops as SIMPLE single commands, never `&&`-chains with variables.
- [git]: verification-gate hashes staged file CONTENT with sha256 — a [VGATE] verifier returning sha1 hashes fails "Hash mismatch"; have it run `shasum -a 256` and echo the exact hex digests. In a task sub-agent session the gate registers verification ONLY from a response that is the exact JSON schema ({"status":"PASS","verified_files":[{path,hash sha256}]}) with the full file list in the prompt — a prose "PASS" report with no per-file hex digests leaves the registry empty and the git op still blocked (PR #459).
- [git]: `git worktree list --porcelain -z` needs git ≥ 2.36 (the `-z` option landed in 2.36.0, not 2.25) — on older git the command fails → treat the cross-check as skipped. git ACCEPTS worktree paths with trailing spaces and embedded newlines (porcelain prints them raw) → never trim path whitespace and never line-split porcelain (NUL-split only) or legit worktrees false-block (main-worktree-guard #351).
- [bash]: real bash resolves the FIRST non-flag positional as the interpreter's script — later tokens are that script's argv, never bash flags (so LAST-positional resolution mis-gates arg-taking invocations: `bash hub-worktree.sh salvage feat/x <repo>` resolves <repo> → non-file → content gate skipped; #444). `-s`/+s and letter-runs containing `s` demote positionals to $0/$1 (stdin script); `-c`/+c = inline (no file); operand-taking options (`-O`/`-o`/`--rcfile` space+`=` forms) skip one operand word; `--` ends option scanning; `+`-toggles mirror `-` runs; mixed-sign words (`-+e`) are rejected by real shells → over-resolving those is harmless. Verify against real bash (dash/bash/zsh) — POSIX doc reading misleads (classify-git extractScriptPath, #520).
- [cache]: negative-TTL retry was dead code — a `x !== undefined` sentinel on a `string | null | undefined` cache short-circuits on a cached FAILED (null) resolution, making a transient failure terminal for the session → distinguish resolved-null from unresolved with `typeof x === "string"` (or a separate resolved flag) and pin the failure→retry sequence in tests (main-worktree-guard #350).
- [ci-gate]: pipeline-compliance CI blocks merge until the linked issue has a comment with the `<!-- issue-scoping:` marker — post the scoping comment artifact to the issue even when scoping was done inline (the gate reads issue comments, not session state; re-run the failed check with `gh run rerun <run-id>` after posting). For complexity:standard/complex issues it ALSO needs either a docs/plans/*.md change or a `## Wiring` section inside that scoping comment — a marker-only comment fails check [d] (PR #459).
- [bash]: pi's bash wrapper + review-enforcer trip on git verbs inside inline strings — probe scripts containing `git commit`/`git push` text get blocked by the enforcer's regex; write them to `.mjs` files and run `node <file>` instead of `node -e`.
- [gh]: `gh issue comment` heredocs break on backticks/`$()`/parens in the body (bash re-processes the command) — always write the body with the `write` tool and pass `--body-file`.
- [extensions]: print-mode-wiring.test.ts fails on ANY raw `process.env.PI_MODE` read in production extension files (zero-raw-reads discipline, #228) — route every read through shared/print-mode.ts (isPrintMode/isPrintModeEnv); my review round hit this at VGATE.
- [extensions]: the deployed extension at ~/.pi/agent/extensions/<name>/ is a COPY, not a symlink — repo changes reach live sessions only via ./sync.sh AND a pi restart (module loads at startup); a running session keeps the OLD module (audit-window lag is expected, not a deploy failure).

- [git-stash]: dropped stash@{0} lost untracked gate scripts (check-ask-*) — default git stash list/show skips third-parent content (git stash show -u reveals it) → inspect `git ls-tree -r stash@{N}^3` before any drop

- [node-ts]: node --experimental-strip-types imports of extension .ts modules silently drop LATER named exports (the last import in a list fails "does not provide an export") → run .ts suites with tsx; never node-strip-types for multi-export module imports (#476).
- [python]: macOS system python3 = 3.9.6 → `X | None` type annotations raise TypeError at def-time (annotation evaluation, "unsupported operand type(s) for |") → use typing.Optional in launchd/python3-farm scripts (#476 Phase 5).
- [launchd]: launchd bash CANNOT read symlinks into ~/Documents (macOS TCC EPERM) — farmed scripts must be REAL copies under ~/.pi/agent/scripts (setup.sh #427); plists need explicit PATH (launchd env is bare).
- [latch-lock]: the provider-exhaustion lock file must be a SINGLE pid token — the TS reader Number(trim)s the whole file, so a two-line python lock (pid+timestamp) reads NaN → TS deems it stale and STEALS a live holder's lock (#476 P1-2).
- [poller-audit]: derivation rule — audit/ledger output dirs must hang off the STATE-FILE path (not ~/.pi/agent defaults) or shell test suites pollute the real durable ledger with synthetic events (#476 P1-3).
- [salvage]: hub-worktree.sh salvage fails on EMBEDDED git repos in the dirty set (`git add` refuses: "does not have a commit checked out") → before salvage, verify each embedded clone is fully pushed to its remote (or snapshot unique commits) and remove it with a pure `rm -rf` command (never compound with git verbs — the guard aborts the WHOLE command on one blocked verb); salvage worktrees land under ~/<repo-name>/.worktrees, NOT the repo dir.
- [vgate]: rebases that absorb origin/main changes to already-verified files change their hashes → the next commit/merge is blocked "Hash mismatch (file changed since verification)" until a fresh [VGATE] dispatch at the new head — expect + plan one re-verify per rebase cycle on strict-protection repos.
- [bash-grep]: GNU grep ERE treats `\t` as a literal 't' while BSD/macOS grep maps it to TAB — a `<TAB>${X}(\t|$)` veto never fires on ubuntu runners (own session left reap-eligible); write a literal TAB byte instead (#536).
- [tests-pgrep]: Linux procps `pgrep -f "<marker>"` via execSync matches the invoking `/bin/sh -c` wrapper (marker text sits in ITS argv) → "gone" probes never observe gone; char-class the first char (`[a]c1-...`) to self-exclude (#536).
