# Scope — what #2843 still owes after PR #3231

## What the thread already settled (measured, not assumed)

PR #3231 (merged `8d9a936b8`, 2026-11-07) closed the **resolver** half of this issue and its own
comment on the issue says exactly what it did NOT close:

> ⚠️ What this PR does **not** close: the shim is still not on the PATH of the cell examined here, so
> the spawn-point gate remains inert there. **That is the install half of this issue and is untouched
> by #3231.**

Re-measured on `origin/main` @ `e3c5fb8f0`:

| the issue's proposed fix | state on main |
|---|---|
| 1. ship the instrument with the gate | ❌ **open** — `install_spawn_gate()` installs only `$DEST/bin/pi`; `ls ~/.pi/agent/bin/` → `pi`, `pi.bak-bootstrap`, no `capacity.sh` |
| 2. self-test at install time | ❌ **open** — neither installer runs the installed gate |
| 3. say which candidates it tried | ✅ done by #3231 (`SPAWN_GATE_CAP_TRIED`, `searched: …` in every abstention and refusal) |
| bound: "an abstention is not recorded durably the way a refusal is" | ❌ **open** — `pi_gate_ledger` has no fork column, so `allowed`-with-the-floor-OFF and `allowed`-with-the-floor-ENFORCED write identical rows |

So this lane delivers 1, 2 and the bound. Item 3 is not re-opened.

## Boundaries

IN:
- `pi-bootstrap/cell-install.sh` — `install_spawn_gate()` also installs
  `scripts/orchestrator-harness/capacity.sh` → `$DEST/bin/capacity.sh` (beside the shim, which is the
  resolver's `$_sgc_here` candidate); `guard_spawn_gate()` byte-compares it and **drives** the
  installed gate's `spawn_fork_state` with every other resolver candidate scrubbed.
- `pi-bootstrap/setup.sh` — the same pair installed, plus the same install-time self-test.
- `scripts/orchestrator-harness/spawn-gate.sh` — `pi_gate_ledger` appends a 13th field,
  `fork=<ok|refused|nodeploy|unknown>`, at all five call sites; a writer that forgets it defaults to
  `fork=unknown` (under-report enforcement, never certify it).
- `scripts/orchestrator-harness/ARCHITECTURE.md` — the `spawn-gate.tsv` row records the new column.

OUT (named, not silently dropped):
- **Environment overrides as the mechanism** (`export O` from the shim, or the `SPAWN_GATE_HARNESS_DIR`
  the issue offers as an alternative). Rejected below.
- **The shim not being on the cell's PATH at all.** That is the separate install gap the #3231 author
  names in the same comment; it is a PATH/activation question about `cell-install.sh`'s `bin/`, not
  the same root as "the instrument is not beside the gate".
- **Making CI execute the two installers end to end.** `tests/pi-shim/run.sh` already states the limit
  ("driving both installers here would duplicate their fixtures"); the artifact half is driven by
  `pi-bootstrap/tests/test-cell-install.sh`.

## Alternatives considered

1. **Have the shim export `O` / an explicit `SPAWN_GATE_HARNESS_DIR` before exec.** Rejected: an
  environment variable is *absent* in exactly the contexts this defect lives in — a launchd job, a
  `tmux new-session` one-liner, a cron entry, an interactive shell — while **directory adjacency cannot
  be absent**. It also makes the fix depend on the shim being the *only* entry point, which is false:
  the same file is sourced by `lane.sh` / `fix-one.sh` from an `$O` that #2095 changed to mean the
  *state* dir.
2. **Add a seventh resolver candidate pointing at `$DEST/bin`.** Rejected: `$_sgc_here` already IS the
  shim's own directory, so the candidate exists and only the *file placement* was missing. Adding a
  path would have made the resolver look right while the install stayed wrong — a green test over the
  defect.
3. **A separate `spawn-gate-ledger` reader/counter for abstentions.** Rejected as category B: the
  question "did the floor run" is answered by `awk -F'\t' '$13 != "fork=ok"'` once the column exists.
  A second tool is process, not capability.
